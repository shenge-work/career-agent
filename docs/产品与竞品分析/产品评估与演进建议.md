> 方法：通读 `docs/v2重构归档/*`、`docs/需求文档/*`、`docs/重设计构思-个人求职Agent工作台.md` + 代码核对（`grep` 验证关键能力落点）
> 结论一句话：**架构已脱胎换骨——从「零后端单文件」跃迁为「本地服务器 + 账号隔离 + 数据库」，工程完成度与测试可信度都大幅提升；但产品重心只完成了「名义升维」，从「编辑器」到「求职 Agent 工作台」的实质闭环仍未落地，且一批 v1 高频能力（导出格式 / 投递体检 / 撤销重做 / 缩略图 / 分享）还在 ROADMAP 待补。**

> ⚠️ 本文是 v2 切换后的**重新基线**，替代 2026-09-20 的 v1 评估。那份评估针对的是已退役的 `serve.js` / `app.js` 单文件架构（file:// 直开、Tauri 壳、飞书同步），其结论（如「一请求崩服务」P0、多简历库从未跑通）对 v2 **已不再适用**，相关能力在 v2 已被重写或拆除。

## 一、v2 架构重评估

v2 把项目从「浏览器里一份 HTML」搬成了「本机起一个 NestJS + Fastify 服务 + React SPA + PGlite（PostgreSQL 18.6 WASM）」：

- **分层清晰**：`src/server/`（auth / tenant / resumes / business / render / ai / collect / users / security）与 `src/web/`（React 工作台）解耦，告别 v1 的 `app.js` 上帝对象。
- **数据本地化**：PGlite 落 `./pgdata`，数据全部在本机，不出电脑；迁移 SQL 手写于 `drizzle/*.sql`，可平替切真 PostgreSQL（P5 待做）。
- **渲染孤岛**：v1 八个 JS + `style.css` 一字不改收编进 `legacy/`，由 `legacy-renderer.ts` 在**每次新建的 vm 沙箱**里加载，`ResumeEditor.applyImported` 取 `preview.innerHTML` 输出 A4 HTML。v1 源码零改动、零复制——这是 v2 能快速切换且「预览契约不变」的关键。
- **双 PDF**：① 矢量版 `pdf.service.ts`（`--print-to-pdf`，文字可选中；无浏览器→501 诚实降级）；② 图片版 `image-pdf.service.ts`（CDP `DevToolsActivePort` 落盘，精确分页）。

**仍要正视的两类风险：**

1. **PGlite 进程内单连接**：迁移 / 导入 / 核查脚本与 dev 互斥，必须停 dev 再跑库操作——这是内测期的真实运维负担，切真 PG（P5）后才能缓解。
2. **内测模型未过生产安全线**：仅监听 `127.0.0.1`、≤10 人本机内测。对外部署前的清单（演示账号处理、版本能力收口、PII 扫描）已在 `docs/v2重构归档/04-运行维护与后续路线.md` §6 列明，发布前必过。

## 二、产品定位已升维，但落地只完成一半

《重设计构思-个人求职Agent工作台.md》（2026-11-04）已把定位从「简历排版 + 投递工具」升维为「个人求职 Agent 工作台」，并定稿命名 **CareerAgent**。这是一次正确的定位跃迁，但当前代码只接住了「架构」，没接住「工作流」：

| 维度 | 旧定位（v1 标尺） | 新定位（Agent 工作台） | 当前落地度 |
|---|---|---|---|
| 产品本质 | 简历排版 + 投递工具 | 求职全流程工作流，AI 是协作者 | ⚠️ 架构就位，工作流缺位 |
| 核心资产 | 自由 CSS 排版引擎 | 求职数据底座 + Agent 编排 | ⚠️ 数据底座（简历/公司/投递）在，编排弱 |
| 主场景 | 打开编辑器编一份简历 | 一个岗位「看 JD → 定制 → 投递 → 面试 → 复盘」闭环 | ❌ 闭环未成形 |
| AI 角色 | 润色等锦上添花 | 贯穿全流程的主线 | ⚠️ 仅独立试用台 + 配置页，未场景化 |

**护城河位次需要重排**（旧标尺的六护城河有三条随 v1 退役失效：file:// 直开、单文件离线、Tauri 桌面）：在新定位下，**「数据自持 + 版本历史」重要性上升**（它们是 Agent 反复读写数据的信任基础），而「自由 CSS 排版」从唯一主角降为能力之一。README 与需求文档里仍散落旧红线表述，需收拢到新的评审标尺（见 §四）。

## 四、当前真实能力清单（以代码为准）

> 判定口径：✅ 已可用 / 🟡 后端就绪、前端入口待补 / ❌ 仍缺（见 ROADMAP / 重设计构思 §3.8）

**✅ 已落地**

- 本地版本历史（PG 承载）：编辑自动留痕、手动快照永不清、恢复前自动备份（可逆）

## 五、竞品视角下的定位（详见另两篇）

- **Reactive Resume**：实时预览 / 模板 / 自托管标杆。CareerAgent 在「自由 CSS 排版」与「数据自持 + 版本历史」上与之差异化，且更强调「求职工作流」而非「排版器」。
- **Resume Matcher**：从「ATS 打分」转型「AI harness（母简历 + JD → 定制版）」证明行业共识方向——这正是 CareerAgent 的 JD 派生主线已经对齐的点。
- **OpenResume**：结构化 PDF 解析是它最值得学的长处，v2 目前**缺导入解析**（v1 的 `pdf-parse` 随 v1 退役，需重新移植）。
- **差异化机会**：三家都强在「做一份简历」，弱在「陪一个人走完一次求职」。以**岗位为第一公民**组织 JD / 简历 / 公司 / 投递 / 面试，是 CareerAgent 真正能建立起护城河的角度。

## 七、不建议做的事（新定位红线，防被带偏）

1. **不做公开云 / 多租户 SaaS**——「个人 Agent 工作台」是单人本地，Agent 是你的私有协作者，不做协作、不做公开注册。
2. **不做通用 Agent 框架 / 对话式产品**——不把工作台做成聊天机器人，Agent 是场景化动作，不是无限对话。
3. **不做自动化「一键海投」**——Agent 帮你准备与跟进，但投递的最终动作由人确认（求职是低频高风险决策）。
4. **不引 react-pdf / 客户端 PDF 引擎、不学 CLI/LaTeX 路线**——自由 CSS 排版仍是护城河，服务端 Chrome 打印是「文字可选中 + 矢量 + 自由 CSS」唯一交集。
5. **不因「Agent」改数据自持定位**——数据仍在本机 `pgdata`，Agent 能力不以「上云」为前提。
