业务规则：R1 同一简历同一时刻最多 1 个 `PUT /api/resumes/:id` 在飞，飞行期间的改动排队合并；R2 只接受最新一次保存的响应，旧响应不得改状态/刷预览；R3 失败保留 draft 并出现「重试」，点重试以当前 draft 立即再存（不受「draft 未变化」限制）；R4 保存错误与导出/JSON 校验/主题切换错误分槽；R5 脏状态注册 `beforeunload`，卸载时 `keepalive` 尽力 flush，「← 简历库」走 `ConfirmModal`；R6 文案统一 `idle/saved`→「已保存」+ 时间戳、`editing`→「有未保存改动」、`saving`→「保存中…」、`error`→「保存失败」；R7 抽出无 DOM 依赖的纯状态机 + 串行队列。

- Given 服务恢复，When 点「重试」，Then 恰好一次保存成功，`GET /api/resumes/:id` 的 payload 与编辑内容完全一致。
- Given 连续快速输入（间隔 <800ms）后停止，Then 网络面板无重叠 PUT 且最终内容与最后一次输入一致（构造「旧请求晚到」单测断言状态不回退）。

验收：Given 详情页，When 快速连续提交 5 处不同字段，Then 5 处改动全部保留（构造并发用例单测）。

**FR-I2-03　简历库搜索与分页边界**（REQ-11，1 人日，影响 `Library.tsx`）
规则：加关键词搜索 + `kind` 筛选（母简历 / 派生版）；删除末页最后一条后 `page` 自动回退到有效页。

**FR-I2-04　附件批量上传体验**（REQ-12，1.5 人日，影响 `Attachments.tsx`）

验收：10 文件混合成功失败时逐项可见，且可只重试失败项；附件 e2e 不回归（涉及 `blobs/` 上传链路）。

**FR-I2-05　账号设置双入口互斥**（REQ-13，0.5 人日，影响 `Account.tsx`）
规则：JSON 编辑框与主题卡共享同一份未提交草稿，切换入口不丢弃另一边的编辑。注意 `settings` 参与跨设备主题同步（`App.tsx` L39–46），不得破坏同步语义。
验收：先编辑 JSON 再点主题卡（或反之），两边改动都不丢；主题同步用例不回归。

**FR-I2-06　落地页 P2 关键 a11y/响应式**（REQ-15，1 人日，影响 `landing/`）
