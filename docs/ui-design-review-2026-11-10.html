P0-01

岗位状态徽章引用 4 个未定义变量，7 条声明全部失效

P0 · 渲染缺陷

岗位卡片的状态标签本应按「有意向 / 已投递 / 面试中 / 已录用 / 已拒绝 / 已撤回」呈现语义色，但 --_gray、--_blue、--_green、--_red 从未在 :root 或任何主题块中声明（实际存在的是 --_steel-medium、--_link-blue、--_teal、--_coral）。CSS 中 rgba(未定义变量, …) 整条声明被丢弃，结果所有状态都是同一种低对比灰字，删除按钮的危险态也失效。

证据

styles.css:1715–1720styles.css:1768–1769styles.css:11–19（变量清单）

全库检索确认这 4 个变量只出现在「使用处」，没有「定义处」。

影响

用户无法在卡片网格里扫读岗位进度，状态筛选与卡片视觉相互矛盾；暗色主题下文字对比度仅约 2.5:1。

/* 最小补丁：在 :root 与 [data-theme='light'] 各补一组别名（1 行） */
:root { --_gray: var(--_steel-medium); --_blue: var(--_link-blue);
        --_green: var(--_teal); --_red: var(--_coral); }

/* 根治方案：删掉 5 套并行的状态色映射，统一为语义令牌 */
:root {
  --status-info-bg:    rgba(110,168,246,.16);  --status-info-text:    #7FB3FF;
  --status-warning-bg: rgba(245,194,107,.16);  --status-warning-text: #F5C26B;
  --status-success-bg: rgba(74,222,155,.16);   --status-success-text: #4ADE9B;
  --status-danger-bg:  rgba(255,139,126,.16);  --status-danger-text:  #FF8B7E;
  --status-neutral-bg: rgba(148,163,184,.14);  --status-neutral-text: #B6BCC8;
}
.status-badge[data-status="applied"]      { background:var(--status-info-bg);    color:var(--status-info-text); }
.status-badge[data-status="interviewing"] { background:var(--status-warning-bg); color:var(--status-warning-text); }
.status-badge[data-status="offered"]      { background:var(--status-success-bg); color:var(--status-success-text); }
.status-badge[data-status="rejected"]     { background:var(--status-danger-bg);  color:var(--status-danger-text); }

验收：6 种状态在暗/亮主题下均可区分，文字对比度 ≥ 4.5:1；全库不再出现未声明的 --_* 变量。

P0-02

全局没有键盘焦点指示器，表单还主动移除了 outline

P0 · WCAG 2.4.7

整份 2,344 行样式表中 :focus-visible 出现 0 次，仅 input:focus / select:focus 改了边框色；而 input、select、textarea 都设了 outline: none。键盘用户进入输入框后几乎看不到焦点位置，登录页、新建岗位、JD 粘贴框均受影响。20 个 TSX 中与键盘相关的处理仅 5 处。

证据

styles.css:249–263styles.css:772–795styles.css（全文 0 处 focus-visible）

影响

违反 WCAG 2.1 AA 2.4.7 Focus Visible；键盘与读屏用户无法完成核心「新建岗位 → 编辑 → 投递」路径。

:root { --focus-ring:2px solid var(--brand-text); --focus-offset:2px; }

/* 统一焦点环：所有可交互元素，仅在键盘操作时出现 */
:where(a, button, input, select, textarea, summary, [tabindex]):focus-visible {
  outline: var(--focus-ring);
  outline-offset: var(--focus-offset);
}
/* 深色主题用亮色焦点环，保证 3:1 非文本对比度 */
:root[data-theme='dark'] { --focus-ring:2px solid #8FA6FF; }

/* 删除 input/select/textarea 里的 outline:none；hover/focus 只做增强 */
input:focus-visible, select:focus-visible, textarea:focus-visible {
  border-color: var(--brand-text);
  box-shadow: 0 0 0 3px var(--brand-soft);
}

验收：纯 Tab 走完登录页与任一表单，每一步焦点位置清晰可见。

P0-03

图标侧栏 10 个入口没有可访问名称，提示气泡仅 hover 触发

P0 · WCAG 1.1.1 / 4.1.2

Layout.tsx 把 GROUPS 定义的分组全部平铺为图标按钮，图标字符标了 aria-hidden，链接本身只有 data-tip 属性（CSS ::after 伪元素）。读屏软件读到的只有一串空链接；键盘聚焦时气泡也不出现（CSS 只写了 :hover::after）；触屏完全没有提示。

证据

Layout.tsx:7–28（GROUPS 分组未被使用）Layout.tsx:81–111styles.css:355–381

影响

导航可发现性差：新用户必须逐个悬停猜测图标含义；辅助技术用户无法导航。分组结构已写好却未渲染，属遗留死代码。

/* 短期：给每个链接可访问名称，并让键盘聚焦也显示提示 */
<NavLink to={n.to} aria-label={n.label} title={n.label}
  data-tip={n.label} className="icon-side-btn">
  <span aria-hidden>{n.icon}</span>
</NavLink>

.icon-side-btn:hover::after,
.icon-side-btn:focus-visible::after { opacity:1; transform:translateY(-50%) translateX(0); }

/* 目标：按 GROUPS 渲染「分组标题 + 图标 + 文字」的 240px 侧栏，
   窄屏折叠为 64px 图标栏并以 aria-label / tooltip 兜底 */

验收：读屏逐个朗读 10 个入口名称；Tab 聚焦时提示出现；320px 宽下导航仍可完整操作。

P0-04

卡片链接内嵌删除按钮，且删除操作默认完全隐藏

P0 · 语义 / 触控

Applications.tsx 把整张岗位卡片做成 <Link>，内部又放了一个 <button>。这是无效的嵌套交互元素：读屏与键盘行为不可预测，点击需靠 preventDefault + stopPropagation 打补丁。同时 .job-card-delete 默认 opacity: 0、尺寸 20px，键盘用户永远看不到，触屏也没有 hover。删除确认还用了原生 window.confirm，与简历库已有的内联 Modal 不一致。

证据

Applications.tsx:161–185Applications.tsx:180styles.css:1746–1770Library.tsx:577–593（已有 Modal）

影响

桌面端删除入口不可见；移动端不可达；危险操作缺少统一的、可键盘操作的确认流程。

/* 结构：链接与按钮同级，卡片本身不再是可点击元素 */
<article className="job-card">
  <Link className="job-card-main" to={`/applications/${a.id}`} aria-label={`查看 ${a.position}`}>…</Link>
  <button className="job-card-delete" aria-label={`删除 ${a.position}`}
          onClick={() => openConfirm(a.id)}>×</button>
</article>

.job-card-delete { min-width:44px; min-height:44px; opacity:1; }
.job-card:focus-within .job-card-delete { outline:2px solid var(--brand-text); }
/* 8 处 window.confirm 统一替换为 <ConfirmDialog> */

验收：卡片内无嵌套交互元素；删除按钮常驻且触控区 ≥ 44×44px；全库 0 处 window.confirm。

P0-05

菜单与弹窗缺少键盘管理、焦点陷阱和语义标注

P0 · WCAG 2.1.2 / 2.4.3

账户下拉、行内「⋯」菜单、删除确认框都只做了「点击外部关闭」（mousedown 监听）：没有 Escape 关闭、打开时不转移焦点、关闭后不归还焦点、没有焦点陷阱；role="menu" 的子项不是 menuitem，role="dialog" 缺 aria-labelledby。简历库列表行用 <li onClick> 实现选中，无 tabIndex 与键盘事件，键盘无法选中。

证据

Layout.tsx:50–59 / 118–163Library.tsx:44–108Library.tsx:295–299Library.tsx:577–593

影响

键盘用户会被困在弹出层外，或弹窗关闭后焦点丢失到文档顶部；读屏无法理解弹窗用途。

/* 统一 useDialog / useMenu 契约（每个浮层都必须满足） */
1. 打开：焦点移入浮层第一个可交互元素
2. 期间：Tab / Shift+Tab 在浮层内循环（焦点陷阱）
3. Escape：关闭，并把焦点归还给触发元素
4. 语义：role="dialog" + aria-modal="true" + aria-labelledby
         role="menu" + 子项 role="menuitem" + 方向键导航
5. 可点击行：改为 <button> 或补 role="button" tabIndex=0 onKeyDown(Enter/Space)

验收：所有浮层可纯键盘打开、操作、关闭；关闭后焦点回到触发按钮。

05

P2 · 体验完整度与性能

属于「从能用到好用」的一层，建议在令牌与组件就位后再做。

状态覆盖不完整

  • 加载态只有 加载中… 纯文本，全库 0 处骨架屏；首页 5 个指标卡同时加载时整页跳动。
  • 按钮 :active 状态全库缺失；busy 仅替换文字，无 spinner / 进度反馈。
  • 空状态 .empty 只有一句灰字，没有引导动作；错误态 .alert 无 role="alert"。
  • 无 prefers-reduced-motion 适配；无 200% 文本缩放验证。

响应式细节

  • 所有断点都是 max-width 降级，未采用移动优先；5 个断点值互不成体系。
  • 10+ 图标在窄屏仍纵向排满 64px 图标栏，.icon-sidebar 无滚动 / 折叠策略。
  • .dash-stats 最窄只降到 2 列，320px 宽下指标卡挤压；.editor-grid 在小屏仍保留 min-height: 620px。
  • 内容宽度不统一：.content-body 1280px、.dashboard 960px、.detail-page 960px。

  • 简历列表每行渲染一个 450×637 的完整 iframe 文档 再 scale(0.1955) 缩略（styles.css:1113–1122）。已设 loading="lazy"，但长列表仍会累积文档实例与内存；建议改为服务端生成静态缩略图或 canvas 位图缓存。

  • 单文件 65.8 KB CSS 无按需拆分，但体量尚小；优先级低于令牌整理。
06

优化方案 · 设计令牌系统

保留现有暗/亮双主题机制与 RGB 三元组写法，重新划分 primitive → semantic 两层，并把「填充色」与「文字色」拆开。
核心决策：把 --accent 拆成 --brand（填充/边框，保持 #3645D9）与 --brand-text（文字，暗色 #8FA6FF / 亮色 #2E3FC4）。这是解决链接对比度 2.84:1 的关键，同时保留品牌色相。所有语义状态色同时提供 -bg 与 -text 两个变体，5 套并行映射据此收敛为 1 套。

令牌分层

01
Primitive
原始色板 RGB 三元组、字号、间距、圆角数值；不带语义，禁止在组件中直接引用。
02
Semantic
bg / surface / border / text / muted / faint / brand / status-*；按主题块覆盖。
03
Component
btn-primary-bg、card-radius、input-border；组件内部只引用这一层。
04
Page
页面布局变量（内容宽度、栏宽、顶栏高）；不再出现裸 px 数值。

优化方案 · 信息架构与响应式

工作台已有 10 个功能入口；把它们从「猜图标」变成「看得懂、找得到」是收益最高的一处改动。

导航与顶栏

  • 恢复分组：直接使用 Layout.tsx 已定义但未渲染的 GROUPS（工作区 / 智能工具 / 系统），分组标题可折叠。
  • 侧栏双形态：展开 240px（图标 + 文字 + 分组）、折叠 64px（图标 + aria-label + tooltip）。激活态用 3px 左侧指示条 + 柔和背景，不只靠底色反差。
  • 顶栏承担定位：面包屑 + 当前页标题 + 全局搜索（岗位 / 简历 / 公司）+ 账户入口；高度固定 56px，用 flex 而非 calc(100vh - Npx) 推导内容高度。
  • 统一内容宽度：全站 max-width:1120px，取消 1280 / 960 混用；详情页与仪表盘共用同一栅格。
  • 收敛主操作：每个页面右上角固定一个 primary Button；主按钮统一使用 --brand 填充 + --on-brand 文字，不再随主题反色。

落地路线与验收

按「先止血、再建模、后打磨」三阶段推进，每阶段都有可独立验收的产出。
PHASE 0 · 止血

修复确定性缺陷

  • 补齐 4 个未定义颜色变量，或直接切换到语义状态令牌
  • 加入全局 :focus-visible 焦点环，移除表单 outline:none
  • 为图标导航加 aria-label 与 focus 触发的 tooltip
  • 拆解 <Link> 内嵌 <button>，删除按钮常驻 + 44px 热区
  • Dialog / Menu 补齐 Escape、焦点陷阱、语义标注
验收：P0 五项全清；纯键盘可完成「登录 → 新建岗位 → 编辑 → 删除」闭环。
PHASE 1 · 建模

令牌化与组件抽取

  • 拆 tokens.css / base.css / layout.css，引入 @layer 层叠顺序
  • 收敛 16 种字号 → 7 级、15 种圆角 → 5 级、5 个断点 → 4 级
  • 状态色 5 套 → 1 套 StatusBadge；清理重复选择器与死样式
  • 落地 Button / TextField / Card / Dialog 四个高频组件，优先替换首页与岗位页
  • 统一顶栏、面包屑、1120px 内容宽度
验收：新增一个页面时不再需要写任何新的颜色 / 字号 / 圆角裸值。
PHASE 2 · 打磨

体验完整度与性能

  • 补齐骨架屏、按钮 loading / active、错误与空状态引导
  • 移动优先断点重做，底部 Tab 与抽屉导航
  • Unicode 字符图标迁移为内联 SVG sprite
  • 简历缩略图改为静态图缓存，去掉按行 iframe
  • 暗 / 亮主题全页走查，接入 prefers-color-scheme 作为首次默认值
验收：AA 清单逐项通过；320px / 200% 缩放 / 双主题无布局溢出。
