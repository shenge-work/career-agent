# 桌面客户端（Windows / macOS）

CareerAgent 的桌面版不是另一套应用，而是把现有的「NestJS + PGlite + React SPA」原样装进一个
Electron 壳里：主进程负责窗口，内嵌的 utility process 在本机回环上跑同一个服务，窗口加载同一个
前端。**业务代码、数据库、鉴权、同步协议一行都不用重写。**

## 为什么是 Electron 而不是 Tauri

| 约束 | 结论 |
|---|---|
| 服务端是 NestJS + Fastify + PGlite（PostgreSQL WASM）+ `@node-rs/argon2`（N-API 原生模块） | Electron 自带完整 Node 运行时，可直接跑编译后的 `dist-server`；Tauri 需要额外打包并维护一个 Node sidecar，还要处理 wasm / 原生模块在两平台的 ABI |
| 数据必须留在本机、前端调用相对路径 `/api`、会话 cookie 依赖同源 | 桌面端用 `127.0.0.1:<随机端口>` 同时提供 API 与 SPA，与浏览器版完全同构 |
| v1 的 `file://` 单文件 / Tauri 打包已退役 | 本轮是 v2 架构下的重新实现，不复用 v1 资产 |

## 运行架构

```
Electron 主进程 (desktop/src/main.ts)
  ├─ 单实例锁 / 原生菜单 / 窗口 / 外链拦截 / 优雅退出
  └─ utilityProcess.fork(desktop/dist-main/server-entry.js)   ← 独立 Node 进程，UI 不会被 WASM 卡住
        ├─ createServerApp()            ← src/server/main.ts 的同一个入口
        ├─ 静态托管 dist-web/            ← 与 /api 同一个端口、同一个 Origin
        ├─ PGlite 数据 → <userData>/data/pgdata
        ├─ 附件字节  → <userData>/data/blobs
        └─ listen(0, 127.0.0.1) → 真实端口通过 IPC 回传主进程
              ↓
        BrowserWindow.loadURL(http://127.0.0.1:<port>/)
```

端口由系统分配，绝不占用固定的 3000；`DB_CLIENT_PORT` / `DEV_SKIP_AUTH` 等开发态开关会被
主进程从子进程环境里剔除。

## 目录

| 路径 | 作用 |
|---|---|
| `desktop/src/main.ts` | Electron 主进程：单实例、菜单、窗口、服务进程生命周期、`--smoke` 自检 |
| `desktop/src/server-entry.ts` | 内嵌服务入口：补齐 env → 加载 `dist-server` → 注册静态路由 → `listen(0)` |
| `desktop/src/paths.ts` | app 根 / 用户数据目录 / 各资源目录的唯一解析入口（纯函数，有单测） |
| `desktop/src/static.ts` | 同源静态托管：MIME、路径穿越防护、SPA fallback、`/api/*` JSON 404 |
| `desktop/src/preload.ts` | 只暴露「查看信息 / 打开数据目录 / 复制地址」，不放开 Node 能力 |
| `desktop/setup.html` | 首次运行建号向导（由内嵌服务同源提供） |
| `desktop/scripts/generate-icons.mjs` | 无第三方依赖生成 `icon.png / icon.ico / icon.icns` |
| `desktop/scripts/launch.cjs` | 从 npm script 启动 Electron 的包装器，剔除宿主注入的 `ELECTRON_RUN_AS_NODE` |
| `electron-builder.yml` | Win NSIS + portable / macOS dmg + zip 配置 |

服务端为打包做的四处小改动：

- `src/server/main.ts` 拆出 `createServerApp()`，并给 CLI 启动加 `require.main === module` 守卫；
- `src/server/db/migrate.ts` 支持 `CAREER_AGENT_MIGRATIONS_DIR`（安装包里 `drizzle/` 是只读资源）；
- `src/server/collect/collect.service.ts` 在 Electron 下为采集脚本加 `ELECTRON_RUN_AS_NODE=1`；
- 新增 `src/server/setup/`：`GET /api/setup/status`（判断是否需要打开首启向导）与
  `POST /api/setup/bootstrap`（本地自助建号，等价于 `npm run seed:user` 的图形化版本）。
  账号一律平等：不写入角色、不建立隶属关系，也不限制「只能创建一次」。

## 开发态

```bash
npm install
npm run dev                 # 另开一个终端：Vite 5173 + API 3000
npm run desktop:dev         # 再开一个终端：Electron 壳指向 5173
```

开发态不启动内嵌服务，仍用 `npm run seed:user` 建号；`--desktop-dev` 也可以通过
`CAREER_AGENT_DESKTOP_URL` 指向别的前端地址。

> `desktop:dev` / `desktop:smoke` 走 `launch.cjs` 而不是直接 `electron .`：某些 IDE /
> Electron 工具的集成终端会全局设置 `ELECTRON_RUN_AS_NODE=1`，使 Electron 退化成纯 Node
> （主进程里 `app` 为 undefined）。包装器启动前清掉该变量；`serverEnvironment()` 也会把它
> 从内嵌服务进程环境里剔除，保证 utility process 的 `process.parentPort` IPC 可用。

不依赖 GUI 的自动化自检（会真的拉起内嵌服务与 PGlite，但不创建窗口）：

```bash
npm run desktop:smoke
# [smoke] /api/setup/status → 200 | / → 200 | /__desktop/setup → 200
```

## 构建与打包

```bash
npm run desktop:build       # npm run build（tsc + vite）+ 编译 desktop/tsconfig.json
npm run desktop:pack:win    # Windows：NSIS 安装包 + portable exe，输出到 release/
npm run desktop:pack:mac    # macOS：dmg + zip（x64 / arm64），输出到 release/
npm run desktop:pack:win:dir  # 只生成免安装绿色版 release/win-unpacked/（不下载 NSIS 工具）
```

绿色版双击 `release/win-unpacked/CareerAgent.exe` 即可使用，数据与安装版完全相同。
electron-builder 打 NSIS 安装包时需要额外下载 `nsis-resources` / `winCodeSign` 等工具包；
境内网络若返回 502，可设置镜像后重试：

```bash
ELECTRON_BUILDER_BINARIES_MIRROR=https://registry.npmmirror.com/-/binary/electron-builder-binaries/ npm run desktop:pack:win
```

- Windows 安装包请在 Windows 上构建；macOS 的 dmg 需要在 macOS 上构建（跨平台无法生成 dmg）。
- `asar: false` 是刻意的：PGlite 的 wasm/data、`@node-rs/argon2` 的 `.node`、以及内嵌服务对
  `app/node_modules` 的普通 Node 解析都需要真实文件路径。
- 未配置 Apple Developer 证书时 `mac.identity: null` 产出未签名包，用户首次打开需右键「打开」
  或执行 `xattr -cr /Applications/CareerAgent.app`；正式分发请补签名与公证配置。
- Electron 二进制下载慢时可设置镜像：`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`。

## 首次运行与数据目录

第一次启动（库里没有任何账号）会自动打开「欢迎使用 CareerAgent」向导：填邮箱 + 至少 8 位密码即
创建一个**普通独立账号**（无角色、非管理员），随后自动登录并跳进主界面。已有账号后向导不再出现，
但仍可在登录页「创建新账号」持续创建互相独立的账号；重复邮箱返回 409。

数据目录由 Electron `userData` 派生，**与安装目录分离**，备份 / 卸载 / 迁移只需拷这一个目录：

| 平台 | 路径 |
|---|---|
| Windows | `%APPDATA%\CareerAgent\data\` |
| macOS | `~/Library/Application Support/CareerAgent/data/` |

下挂 `pgdata/`（PGlite）与 `blobs/`（sha256 内容寻址的附件字节）。菜单「文件 → 打开数据目录…」
可直接打开。开发态沿用仓库根的 `./pgdata`，两者互不干扰。

## 安全边界

- 服务只监听 `127.0.0.1`，沿用 Host/Origin 回环守卫；页面与 API 同源，cookie 行为与浏览器版一致。
- 渲染进程 `contextIsolation: true` / `nodeIntegration: false`，preload 不暴露 fs 或子进程能力。
- 安装包默认关闭 `DB_CLIENT_PORT`（DBeaver 桥）与 `DEV_SKIP_AUTH`。
- 初始化端点只暴露 `{ needsSetup: boolean }`，且只在 `users` 为空时可写；它替代的是本来就能在
  本机执行的 `seed:user` CLI，没有扩大攻击面。

## 已知限制 / 后续

| 项目 | 现状 |
|---|---|
| 矢量 PDF 导出 | 依赖本机 Chrome / Edge（`findBrowser()` 已覆盖两平台常见路径），也可用窗口 `Ctrl/Cmd+P` 另存为 PDF；后续可改用 Electron 自带 `webContents.printToPDF()` 去掉外部依赖 |
| BOSS 聊天采集 | 仍要求用户自行用带调试端口的 Chrome 打开页面；桌面端已处理 Electron 下 `process.execPath` 当 Node 解释器的问题 |
| 自动更新 | 未接入，当前为手动下载新安装包（数据目录独立，覆盖安装不丢数据） |
| 代码签名 / 公证 | 未提供证书配置，需发布者自行补 `win.sign` / `mac.notarize` |

## 排障

| 现象 | 检查 |
|---|---|
| 启动即报「未找到服务端构建产物」 | 先跑 `npm run desktop:build` |
| 启动超时 60 秒 | 看数据目录是否可写；`npm run desktop:smoke` 看内嵌服务日志 |
| 页面白屏但 API 正常 | `dist-web/index.html` 是否生成、vite build 是否成功 |
| PDF 导出报「未找到 Chrome」 | 安装 Chrome / Edge，或在菜单里查看后手动设置 `CHROME_PATH` |
| 端口冲突 | 不会：内嵌服务 `listen(0)` 由系统分配端口 |
| 报 `Cannot read properties of undefined (reading 'requestSingleInstanceLock')` | 用 `npm run desktop:*`（经 `launch.cjs`）启动；不要在带 `ELECTRON_RUN_AS_NODE=1` 的终端里直接 `electron .` |
| NSIS 打包报 `502 Bad Gateway` | electron-builder 下载工具包失败，与项目代码无关；设 `ELECTRON_BUILDER_BINARIES_MIRROR` 或稍后重试，急用先跑 `desktop:pack:win:dir` 出绿色版 |
| 打包目录里混进了 `.tmp-*` 等临时产物 | `electron-builder.yml` 已排除；重跑前把项目根的临时构建目录移走，别让 `**/*` 把它们收进去 |
