## 2. 逐文件改动说明

### ① `src/web/pages/editor-autosave.ts`（T01 · 纯逻辑内核）

严格按 §3.3.1 逐字导出：`AutosaveStatus` / `AutosaveView` / `SaveTransport` / `AutosaveOptions` / `AutosaveController` / `canonical()` / `formatSavedAt()`。

- `canonical(payload)`：只删**顶层** `savedAt`（数组/非对象直序列化），沿用 `legacy/js/app.js` L774 口径；不递归处理 `data` 内字段。
- `formatSavedAt(ts)`：本地 `getHours/getMinutes/getSeconds` + `padStart(2,'0')` → `HH:mm:ss`，不依赖 locale/Intl。
- 状态机内部字段：`baseline`（canonical 字符串）、`pending`（最新快照，恒 0/1）、`lastDraft`、`seq`、`inflightSeq`、`inflight`、`status`、`saveError`、`lastSavedAt`、`disposed`、`waiters`、`lastEmitted`。
- `isStale(seq) = disposed || inflightSeq===0 || seq!==inflightSeq || seq!==seq`；命中**整体丢弃响应**，不 emit、不改 baseline、不 onDrained、不 resolve 等待者。
- `pump()` 只在 `!disposed && !inflight && pending!==null` 时发一个请求；`onSettled` 成功且 pending 非空时 `drained=false` 并立即续发，排空才 `status='saved'` + `onDrained()` + `resolveWaiters()`。
- `reset()` / `dispose()` 都推进 `seq` 并清 `inflightSeq`，使旧在飞响应一律失效；`reset` 可复活 controller（供 id 切换重建后灌基线），`dispose` 不 emit（卸载后不触发视图更新）。
- `flushAndWait()` **永不 reject**：失败写 `view.saveError` 后 resolve；队列忙时等待排空。
- `isIdle()` 定义为 `!disposed && !inflight`（无在飞写请求），使防抖窗口内（仅 pending 待发）的卸载也能安全 flush，同时严格避免与在飞 PUT 乱序。
- `commit()` 在 `error` 态直接 no-op：满足 §2.3「error 态不自动重试」（P1 的 R8 不做），重试只由 `retry()` 触发。
- `touch()` 增强：撤销回到 canonical 基线且无在飞、非 error 时清 pending 并回 `saved`，避免内容相同的多余 PUT。

### ② `test/editor-autosave.test.ts`（T01 · 14 例）

风格对齐 `test/theme.test.ts`；`deferred()` 构造可控 transport，`tick()` 等待微任务链。用例清单：

1. canonical 剥离顶层 savedAt（仅时间戳不同指纹相同）
2. canonical 对 `data` 内改动敏感、不递归删嵌套、null/数组边界
3. formatSavedAt 输出 `HH:mm:ss`（03:04:05 / 13:47:09 / 正则）
4. 幂等：内容未变 `touch+commit` → transport 0 次
5. 单飞合并：在飞期间多次 `touch+commit` 只发 1 次，pending 合并为最后内容
6. 排空续发：第二次内容最新、`onDrained` 恰好 1 次、成功后不重复 PUT
7. **乱序丢弃**：reset 后旧 deferred 晚 resolve → onChange 不触发、状态/时间戳/baseline 不回退、onDrained 不重复
8. 失败可恢复：reject → error + saveError；`retry` 以最新 draft 成功
9. error 态 `touch` 不清 saveError、`commit` 不自动重试（R8 不做）
10. `reset` 清空状态并按新基线幂等；撤销回基线不产生多余请求
11. `dispose` 后所有响应丢弃、view 归 idle、isIdle=false
12. `flushAndWait` 队列忙时等待排空后 resolve，落库最新 draft
13. `flushAndWait` 失败也 resolve 且写 saveError
14. `isIdle` / `dirty`：inflight 时 false、排空后 true；脏标记成功清除、失败保持

### ③ `src/web/pages/Editor.tsx`（T02 / T03 / T04）

- **删除**：`status` state、`baselineRef`、`saveM` useMutation、旧 800ms effect（L764–795）、保存成功回调里的 `setJsonText`、`setStatus`、`setError('')` / `setError(message)` 两处。

## 6. 相对设计文档的细化 / 偏差说明（均已论证）

1. **`canonical` 未直接 import 进 Editor.tsx**：设计 T02 的 import 清单含它，但两处灌基线按主理人裁决改为 `ctrl.reset(p)`（内部已 canonical），Editor 层无调用点，故不引入未使用符号。
2. **transport 内组装 `saving.savedAt`**：主理人给出的 transport 字面是 `put(..., { payload })`；为遵守「`saving.savedAt` 保留写入 payload 不许删」，在 transport 内深拷贝并打时间戳，请求体仍是 `{ payload }`，契约零变化。
3. **`commit()` 在 error 态 gate**：§3.3.2 防抖 effect 直接调 `commit()`，但 §2.3 状态表要求 error 态不自动重试；gate 放在状态机内部，React 代码保持设计原样。
4. **`isIdle()` 定义为「无在飞请求」**：使防抖窗口内卸载也能 flush（否则会丢 800ms 内的编辑），同时仍严格避免与在飞 PUT 乱序；单测覆盖。
5. **StrictMode 生命周期令牌**：设计未预见 `main.tsx` 的 `React.StrictMode`；若不处理，dev/QA 手工验收时自动保存会失效。属必要加固，未改接口。
6. **`touch()` 回基线优化**：撤销到 canonical 基线时取消 pending，避免内容相同的多余 PUT（§2.1「保存成功后不重复 PUT」的加强）。
