## 一、背景与现状问题

2026-11-03 已完成板块拆分：投递平台 / 状态 / 入库 / 锁简历 / IM 聊天全部迁至「投递管理」，`/companies` 改为纯「公司档案」。当前实现（`js/views/company-view.js` + `js/store/company-store.js`）能跑，但停留在「能用」而非「好用」：

| # | 现状 | 问题 |
|---|------|------|
| 1 | 列表是 6 列纯表格 | 信息密度低，公司多了无法扫读；无筛选、排序、视图切换、批量操作 |
| 2 | 统计条仍显示「曾投递」 | 与「投递无关」的定位冲突，应移除 |
| 3 | 详情是单栏长滚动 | 六维调研 + JD 卡片混在一起，缺锚点，找信息靠滚 |
| 4 | 没有摘要 / 完整度概念 | 看不出这家公司「资料齐不齐」「缺哪块」 |
| 5 | 编辑是全量模态 | 基本信息 + 全部调研 + 全部 JD 塞一个弹层，改一条调研也要开整页 |
| 6 | 无就地编辑 | 单条调研的修正成本高 |
| 7 | 无汇总 / 导出 | 用户最初诉求「方便汇总回复」尚未闭环 |
| 8 | 来源可追溯性弱 | 有 `platform/date/url` 但无可视化、无时间线 |
| 9 | 与投递只有单向引用 | 投递详情可跳公司档案，公司侧看不到「被哪些投递引用」 |
| 10 | 导入靠外部脚本 | PDF / 截图报告要手工拆条，没有前端批量导入入口 |

## 二、定位与边界（设计铁律）

**一句话定位**：公司档案 = 求职情报底座，回答「这家公司是什么、值不值得投、面试聊什么」；投递管理回答「我投到哪一步」。

四条不可破的契约：

1. **公司侧不出现任何投递状态**。列表、详情、编辑、简报都不显示「已投递 / 已入库 / 锁简历 / 投递日期」。统计条移除「曾投递」。
2. **`applied` 只是隐藏关联标记**（供投递板块自动建档），不参与 UI 渲染；设计上可长期保留但不展示。
3. **跨板块只读**：投递详情内嵌 `CompanyView.companyBriefHtml()`；公司详情列出关联投递记录并支持跳转 `#/tracker/<id>`，但**不允许在公司侧修改投递字段**。
4. **单一事实源**：`data/companies/companies.json`（`/api/companies`）是公司事实唯一来源；投递侧 `companyId` 是外键。任何写入都走 `CompanyStore.normalizeCompany()` 规整。

### 用户场景

- **投递前**：查公司 → 判断要不要投、用哪版简历、JD 技能是否匹配。
- **收到 HR 回复 / 面试前**：一键生成「公司简报」→ 复制到聊天或作为面试提纲。
- **面试准备**：按维度复习团队 / 融资 / 竞品 / 风险，对照 JD 技能点。
- **长期沉淀**：把官网、企查查、脉脉、公众号、BOSS 等各平台信息挂到同一家公司下，随时更新不丢。
- **复盘选择**：多公司并排对比行业、规模、融资、JD 薪资与技能要求。

## 四、信息架构与 UI 规格

### 路由

| 路由 | 页面 | 说明 |
|------|------|------|
| `/companies` | 档案库 | 搜索词 / 筛选 / 视图 / 滚动位置记在会话态，返回时恢复 |
| `/companies/:id` | 公司详情 | 支持锚点 `#dim-融资情况`、`#jd-xxx` |
| `/companies/:id?edit=1` | 详情 + 直接打开编辑抽屉 | 供「＋ 补充某维度」使用 |
| `/companies/compare?ids=a,b` | 多公司对比 | 2–4 家 |

### 列表页

- 顶部：`← 返回` / 标题「公司档案」/ 降级提示 / 搜索框（`/` 聚焦）/ 视图切换 / 「＋ 新建公司」。
- 统计条 4 项：**公司档案、调研条目、岗位 JD、平均完整度**（替换原「曾投递」）。
- 筛选 chip 行：全部 / 有 JD / 缺维度（可展开选具体维度）/ 最近 7 天更新；**行业下拉（按一级门类分组，显示每类公司数）**；排序下拉。
- 搜索框支持**行业同义词扩展**（见 §10.4）：输入「大模型 / 芯片 / 银行 / AR」等词命中对应行业门类的公司；命中时在筛选行显示「按行业匹配：AI 应用 ← 大模型」提示，可一键清除。
- 卡片：公司名（15px / 500）+ **标准行业类目 chip** · 地点 chip + **六格完整度微条** + 调研数 / JD 数 + 更新时间 + 勾选框；hover 抬升并显示「查看详情」。
- 表格视图用于批量操作（勾选、对比、删除）。

### 详情页

- 头部：公司名（20px / 500）、meta chip、官网外链、更新时间、「生成简报」「编辑」「⋯」（复制档案链接 / 导出 / 删除）。
- **一句话摘要**：左侧 2px 灰竖线，13.5px 次要色；可就地编辑。
- **信息完整度条**：6 段，已覆盖 = 实心深灰，缺失 = 描边浅灰；右侧「＋ 补充 盈利情况」直接打开抽屉对应分区。
- 主体：`190px sticky TOC + 自适应内容流（max 880px）`。TOC 顺序（v2）：**我的判断 → 六个维度 → 岗位 / JD → 薪资水平 → 福利制度 → 面试与面经 → 图片 / 相册 → 内容链接 → 风闻 / 待核实 → 备注 → 关联投递 → 更新记录**；滚动用 IntersectionObserver 高亮当前项。TOC 只列出有内容或可补齐的项，空板块收进「更多」避免导航过长。
- **两张时序图的位置**：「融资情况」维度内嵌**融资阶梯累计图 + 轮次时间线**（双视图切换）；「公司简介」维度内嵌**战略转型阶段泳道图**。图与原文本叙述同屏共存——图看趋势、文本看依据，点击图节点可跳到对应来源调研卡片。图一律原生内联 SVG，只用灰阶，空数据不画空图。
- 调研卡片：`来源平台 chip + 日期 + 来源链接 ↗ + 新鲜度（N 个月前 / 可能过期）` 在头部；正文纯文本（`esc()`，不走富文本）；底部操作 `就地编辑 / 复制 / 上移 / 下移 / 删除`；同维度多源冲突时并排显示、互不覆盖。
- JD 卡片沿用现有 `.co-jd-*`（岗位名 + 薪资、城市·经验·学历、招聘者、职责 / 要求、技能 / 福利 chip、记录于 + 来源 + 岗位链接）；**JD 薪资区间与「薪资水平」区间图叠加对照**，**JD 福利 chip 与「福利制度」表对照口径差异**。
- v2 新板块的视觉隔离：正式情报用实线卡片；**风闻 / 待核实**用虚线边框 + 灰底 + 区块标题文字水印，绝不混入正式调研；图片相册用统一 4:3 灰底裁切 + 灯箱；薪资图用原生内联 SVG。
- **关联投递（只读）**：每条显示岗位 / 平台 / 日期 / 状态 + 「查看 ↗」；明确标注「只读，状态在投递管理维护」。
- 从投递详情跳来时，顶部插入回退条「来自投递：平安银行 · Agent 研发高级工程师　← 返回投递详情」。

### 编辑抽屉

右侧 420–480px 抽屉，背景遮罩；分区 `<details>` 折叠，默认展开「基本信息」；底部固定「保存 / 取消」。抽屉内字段与现有 `normalizeCompany` / `normalizeJd` 完全对齐，避免另造数据格式。就地编辑单条调研时，只替换那一张卡片为输入态，保存后局部刷新该卡片。

### 视觉令牌（严格黑 / 白 / 灰）

- 只用 `--ui-*` 变量：`--ui-card / --ui-panel / --ui-panel-head / --ui-text / --ui-muted / --ui-faint / --ui-border / --ui-border-soft / --ui-solid-bg / --ui-solid-text / --ui-focus-ring`。**禁止任何彩色**（含 BOSS 红橙、状态色）。
- 强调靠：字重（400 / 500 两档）、字号、边框粗细、灰阶深浅、留白。
- 组件：chip = 0.5px 描边圆角 6px；卡片圆角 8px、1px 描边；分隔线 `--ui-border-soft`；焦点环 2px；间距 8 / 12 / 16 / 24。
- 暗色：全部走变量，禁止写死 `#fff` / 深色值；`@media (prefers-reduced-motion: reduce)` 关闭平滑滚动与过渡。
- 空态：一句文案 + 主行动按钮（新建 / 导入）；危险操作二次确认。

## 五、交互细则

1. **主路径**：列表 → 点卡片进详情 → TOC 锚点滚动 → 就地编辑 / 生成简报 → 返回列表并恢复搜索词、筛选、视图、滚动位置。
2. **就地编辑**：点卡片「就地编辑」→ 该卡片变 textarea + 来源 / 日期 / 链接输入 → 「保存」只更新这一条 `research` 并局部重绘；「取消」还原；`Esc` 退出。
3. **维度补齐**：完整度条上缺失维度的「＋ 补充」→ 打开抽屉并自动展开该维度、预选 `dim`。
4. **简报**：弹层勾选维度 / JD / 备注 → 实时生成 Markdown（公司名、摘要、各维度要点、JD 技能与薪资）→ 复制 / 导出 .md / 打印 PDF。
5. **对比**：列表勾选 2–4 家 → 并排表格（基本信息、六维有无与摘要、JD 薪资 / 技能）。
6. **跨板块**：投递详情「查看完整档案 ↗」→ 公司详情 + 回退条；公司详情「关联投递」→ `#/tracker/<id>`。两处只读。
7. **键盘**：`/` 聚焦搜索、`Esc` 关闭抽屉 / 弹层 / 就地编辑、`⌘/Ctrl+S` 保存抽屉、`j/k` 列表上下移动（P1）。
8. **反馈**：保存中 / 已保存 / 失败重试状态条；删除后 5 秒撤销 toast（会话级）；外链一律 `target="_blank" rel="noopener"`；草稿未保存离开时提示。
9. **可访问性**：按钮 aria-label、表格语义、焦点可见、对比度 ≥ 4.5:1、锚点 `scroll-margin-top` 避开 sticky 头部。

## 六、数据模型

现有字段保持不变，**新增字段一律可选**，`normalizeCompany()` 补全，旧数据零迁移：

| 字段 | 类型 | 说明 | 优先级 |
|------|------|------|--------|
| `summary` | string | 一句话摘要（简报与卡片复用） | P0 |
| `tags` | string[] | 自由标签（融资阶段 / 赛道 / 关注点） | P0 |
| `pinned` | bool | 置顶 | P1 |
| `archived` | bool | 归档（默认列表过滤掉） | P1 |
| `changes` | `{ts, label, detail}[]` | 更新记录时间线（保存时追加，保留最近 50 条） | P1 |
| `sources` | `{title, url, date}[]` | 附件 / 报告来源（PDF 报告原文件链接等） | P1 |
| `media` | `MediaItem[]` | **v2** 图片 / 相册，见 §10.2.1 | P0（随存储方案） |
| `benefits` | `BenefitItem[]` | **v2** 结构化福利制度，见 §10.2.2 | P0 |
| `rumors` | `RumorItem[]` | **v2** 风闻 / 待核实（公司八卦），见 §10.2.3 | P0 |
| `salaries` | `SalarySample[]` | **v2** 薪资样本（按岗位族分箱），见 §10.2.4 | P0 |
| `links` | `ContentLink[]` | **v2** 自媒体 / 内容链接资产，见 §10.2.5 | P0 |
| `verdict` | `Verdict` | **v2（建议补）** 我的判断 / 决策结论，见 §11-A1 | P0 |
| `interviews` | `InterviewItem[]` | **v2（建议补）** 面试与面经，见 §11-A2 | P1 |
| `questions` | `{id, text, status, source}[]` | **v2（建议补）** 待核实问题清单，见 §11-A3 | P1 |
| `industryCategory` | string（类目 id） | **v2** 标准行业类目 id，见 §10.4；旧数据按 `industry` 文本推断，零迁移 | P0 |
| `industryAliases` | string[] | **v2** 该公司自定义行业相关词（补充词表未覆盖的赛道词），参与检索 | P0 |
| `fundingRounds` | `FundingRound[]` | **v2** 连续融资轮次（融资阶梯图数据源），见 §10.5 | P0 |
| `strategyPhases` | `StrategyPhase[]` | **v2** 业务战略阶段 / 转型点（泳道图数据源），见 §10.6 | P0 |

**派生字段（不落盘）**：`dimensionCoverage`（六维覆盖数 / 6）、`researchTotal`、`jdTotal`、`fullText`（搜索用拼接串）、`salaryRangeByRole`（按岗位族聚合后的 low / high / avg）、`freshness`（主要资料时间范围与过期条目数）。

**保持不动**：`research[].{id,platform,dim,content,date,url}`、`jds[].{...}`、`applied`（隐藏）、`createdAt / updatedAt`。

**兼容性**：新增字段全部走 `normalizeCompany` 白名单；`computeStats` 改为返回「公司数 / 调研条目 / JD 数 / 平均完整度」所需的原始计数，或前端自行派生。测试需补：`normalizeCompany` 新增字段缺省补全、完整度计算、简报生成纯函数、`salaryRangeByRole` 聚合、图片简报配置脱敏过滤（默认不含 `rumors` / `media` / `verdict`）。

> **v2 统一来源模型 `SourceRef`（强烈建议先抽象）**：`{platform, url, author, date, credibility, snapshot, status}`。相册、福利、风闻、薪资、链接、调研、JD 七处都有「来源」，各写一套会各自演化；抽象一次全站复用，简报脚注可自动汇总「本简报引用 N 个来源」。现有 `research[].{platform,date,url}` 与 `jds[].source` 在落地时映射到 `SourceRef`，旧数据零迁移。

## 十、v2 补充规格（2026-11-03）

### 10.1 五类新内容的归类（不要都塞进 `research[]`）

用户提的五类内容**数据类型完全不同**，混进现有六维调研会退化成「六堆长文本」，无法对比、无法画图、无法脱敏。按类型拆成独立数组：

| 用户提法 | 板块名 | 数据类型 | 独立字段 | 为什么不进 `research[]` |
|---|---|---|---|---|
| 公司图片 / 相册 | 图片 / 相册 | 媒体（二进制） | `media[]` | 图片不能进 JSON，需要独立存储与灯箱交互 |
| 公司福利制度 | 福利制度 | 结构化清单 | `benefits[]` | 要「有 / 无 / 不详」三态 + 对照 JD 口径，纯文本做不到 |
| 公司八卦 | 风闻 / 待核实 | 未证实文本 | `rumors[]` | 必须与正式情报视觉隔离、默认不进对外简报 |
| 平均薪资 + 低位 / 高位可视化 | 薪资水平 | 数值样本 | `salaries[]` | 需要聚合、画图、统一口径，不是段落 |
| 自媒体平台相关链接 | 内容链接 | 链接资产 | `links[]` | 是「持续跟踪的内容索引」，不是「某条调研的出处」 |

### 10.2 逐项规格

#### 10.2.1 图片 / 相册 `media[]`

字段：`{id, src, thumb, title, kind, alt, source:SourceRef, capturedAt, w, h, bytes}`；`kind` 枚举：办公环境 / 团队 / 产品 / 活动 / 截图 / 其他。

**存储方案（本轮最大技术风险，需先拍板）**：项目是零后端 + `data/companies/companies.json` 单文件 + `file://` 直开 + localStorage 降级（5MB 配额），四条叠加决定了**图片不能内联进 JSON**。

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A 本地媒体目录（推荐）** | 图片落 `data/companies/media/<companyId>/`，`tools/serve.js` 静态托管，`src` 存同源相对路径 | 同源 → html2canvas 可截图、离线可用；缺点：必须 `npm start`，单文件版看不到本地图 |
| B 外链 URL | 存图片 URL（图床 / 公众号图） | 单文件版可用；缺点：防盗链、会失效、**跨域污染 canvas 导致导出图片失败** |
| C 小图内联 data URI | 压缩到 ≤60KB 的缩略图内嵌 | 单文件版可用；缺点：张数受限、JSON 膨胀 |

建议 **A 为主 + B/C 降级**：`npm start` 走本地同源图；`file://` 单文件版把本地图降级为外链或灰阶占位并明确提示。上限：每家 ≤20 张、单张 ≤2MB（本地）/ ≤60KB（内联）。

UI：3–4 列网格，统一 4:3 裁切、灰底占位（无彩色）；灯箱支持左右键切换、`Esc` 关闭、显示标题 / 分类 / 来源 / 采集日期 / alt；支持拖拽批量添加与分类筛选；图片一律 `loading="lazy"`。导出图片简报前把 `src` 归一为同源或 data URI，失败降级为占位框并在预览提示「N 张图片未能内联」。

#### 10.2.2 福利制度 `benefits[]`

**结构化，不做自由文本**。分组固定：作息与工时 / 假期 / 保险与医疗 / 补贴 / 奖金与股权 / 办公与设备 / 其他。每项 `{id, group, label, status:'有|无|不详', detail, source:SourceRef, verifiedAt}`。

UI 为表格：项 / 情况 / 说明 / 来源 / 采集日期；「不详」用浅灰描边空态，缺失项一眼可见，可直接「＋ 补充」。

**与 JD 福利对照（本板块最有价值的点）**：`jds[].benefits[]` 是**招聘方口径**，本表是**员工 / 脉脉口径**。同名词并排显示，口径不一致的条目标「待核实」——例如 JD 写「弹性工作」而员工反馈写「大小周」，这个差异本身就是决策情报。多公司对比与简报都输出这张表。

#### 10.2.3 风闻 / 待核实 `rumors[]`（公司八卦）

字段：`{id, content, credibility:'未证实|单源传闻|多源佐证|当事人|已证实', sentiment:'正面|中性|负面', source:SourceRef, date, verifyStatus:'待核实|已核实|已证伪'}`。**正 / 中 / 负一律纯文字标签，禁止用颜色表达**。

四条铁律：
1. **视觉隔离**：虚线边框 + 灰底 + 区块标题带「风闻 · 未证实」文字水印，绝不混入六维正式调研卡片。
2. **默认不外发**：简报配置里默认不勾选；勾选「包含未核实信息」才能输出，且自动在简报头尾插入「含未证实信息，仅供内部参考」。
3. **图片简报**：勾选风闻后自动加「内部参考 · 请勿外传」文字水印；导出前必须展示预览与包含清单。
4. **合规**：不记录可识别到具体个人的负面内容，不自动抓取，不对外分享含实名八卦的档案。

附舆情时间线：按 `date` 排列，文字标签标正 / 中 / 负，不画彩色趋势图。

#### 10.2.4 薪资水平 `salaries[]` + 区间可视化

字段：`{id, role(岗位族), level(职级), low, high, avg, currency:'CNY', period:'月薪|年薪', months(薪资月数), sampleSize, source:SourceRef, date, note}`。

> **关键判断**：不做「公司整体平均薪资」。整体平均会把 HR 与算法岗混在一起，是误导。用户说的「员工薪资低位 / 高位」落实为**按岗位族分箱**的 `low–high` 区间 + `avg`，同岗位不同职级再分行。

可视化用**原生内联 SVG**（不引入 Chart.js / ECharts，符合原生 JS 护城河）：
- 每行一个岗位族：左侧「岗位 · 职级 · 样本数」，中间灰阶横条从 `low` 到 `high`（浅灰填充 + 1px 描边），`avg` 处一根实心竖线 + 数值，右端标 `low / high` 数值。
- 底部统一 X 轴刻度（如 0 / 20K / 40K / 60K / 80K）与口径说明「¥/月 · 按 13/14/16 薪折算为月薪口径」；币种、周期、月数必须显式可见，否则数据不可比。
- **JD 薪资对照**：把该岗位 `jds[].salary` 解析成区间，用虚线描边条叠在同一行上方，行尾标「招聘区间」；两者错位即「招聘区间虚高 / 偏低」的直观信号。
- 每条样本显示来源与采集日期，附「员工自述样本，仅供参考」；空数据不画空图，显示「暂无薪资样本，去补充」。
- 多公司对比时区间条并排；暗色模式全部走 `--ui-*` 变量，禁止写死颜色。

#### 10.2.5 内容链接 `links[]`（自媒体）

**与 `research[].url` 的区别**：`research[].url` 是「某条调研的出处」；`links[]` 是「公司的持续跟踪内容资产」（账号 / 文章 / 笔记 / 回答 / 话题）。

字段：`{id, platform, title, url, author, kind:'文章|笔记|回答|视频|话题|报告|其他', summary, tags[], collectedAt, publishedAt, status:'有效|失效|待核', linkedResearchIds[]}`。

平台枚举扩展（**全部文字 chip，禁止品牌色**）：微信公众号、小红书、知乎、脉脉、B站、抖音、即刻、掘金、36氪、牛客、看准、OfferShow、企查查、天眼查、官网 / 博客、公众号历史文章、其他。

交互：粘贴 URL 自动识别平台并补全标题（前端规则匹配，不爬虫）；同 URL 去重；**存档快照** `summary` 存正文要点——公众号文章极易被删，链接失效后信息仍在；`status` 点击时校验；「从链接生成一条调研」把要点挂到某维度并形成 `链接 → 调研条目` 追溯链；外链一律 `target="_blank" rel="noopener"`；按平台 / 类型 / 标签筛选。

### 10.3 简报支持生成图片（离线分享）

**三形态共用一份配置**：`BriefConfig { sections[], includeRumors, includeMedia, includeVerdict, format, template, watermark }`。输出：Markdown（复制 / `.md`）、**PNG 竖版长图（默认）/ 卡片拼图 / A4 单页**、打印 PDF。一次勾选，三种输出，避免各写一套内容拼装。

生产链路（**复用已有基建，零新增依赖**）：`buildBriefHtml(config)` → 离屏容器（固定 720px 宽、**强制浅色导出令牌**）→ 项目已有的本地 `vendor/html2canvas.min.js`（离线可用，图片版 PDF 管线在用）→ `canvas.toBlob()` → `URL.createObjectURL` 下载 `公司名-公司简报-YYYYMMDD.png` → 可选 `ClipboardItem` 复制到剪贴板。

八条约束：
1. **强制浅色底**：无论当前亮 / 暗主题，导出图片一律用固定的浅色令牌。黑底截图发给别人不通用，这条最容易被忽略。
2. **跨域图片**：外链图会 tainted canvas → 导出前归一为同源 / data URI；失败降级为灰阶占位并在预览提示数量。
3. **长图分块**：内容过长按 1400px 高切块分别渲染再纵向拼接，页间加浅灰分隔线，避免单次 canvas 过高被浏览器限制（复用 `computePageBreaks` 的「不切行吸附」思路）。
4. **字号放大**：图片内正文按屏幕 1.6–2 倍渲染（13px → 20–24px），行高 1.7，保证手机端可读。
5. **脱敏白名单**：`rumors / media 截图类 / verdict / 内部备注` 默认不勾选；勾选风闻自动加文字水印；导出前展示预览缩略图 + 「将包含以下 N 个板块」确认清单。
6. **完全离线**：字体走系统栈、图片本地、库走本地 vendor，断网可生成；不依赖任何远程资源。
7. **脚注**：页脚标「生成于 WorkBuddy · 信息以原始来源为准」+ 自动汇总「本简报引用 N 个来源」；含风闻时追加「含未证实信息」。
8. **简报模板**：保存常用配置，如「面试前版」（团队 / 风险 / JD / 面经 / 待核实问题）、「分享版」（公司简介 / 融资 / 薪资 / 福利，不含任何未证实与个人判断）。

原型中「生成图片」用纯 Canvas 2D 直绘演示同一份配置与浅色导出效果，不引入外部库，可直接点击预览与下载。

### 10.4 行业分类与「相关行业名词」检索

**问题**：现有 `industry` 是自由文本，6 家公司就有 6 种写法（AI 应用 / 数据服务 / 智能硬件 / 企业服务 / 金融科技 / 半导体），既不能按门类聚合，也不支持「相关词」检索——`allText()` 只做字面拼接，搜「大模型」命中不了「AI 应用」，搜「芯片」命中不了「半导体」，搜「银行」命中不了「金融科技」。

**方案 = 受控词表 + 同义词扩展 + 旧数据推断**，全部前端纯函数，不依赖 AI / 后端：

| 部件 | 内容 |
|---|---|
| `INDUSTRY_TAXONOMY` | 一级门类 → 二级赛道。示例：人工智能（AI 应用 / Agent 平台 / 大模型 / AI 基础设施）、半导体与硬件（芯片设计 / 智能硬件 / AR·VR / 消费电子）、企业服务（SaaS / 数据平台 / 运维智能化 / 开发者工具）、金融科技（银行 / 证券 / 支付 / 保险科技）、互联网与内容（电商 / 游戏 / 内容平台）、其他（教育 / 医疗 / 制造 / 未分类） |
| `INDUSTRY_ALIASES` | 别名 → 类目 id，多对一。示例：`大模型 / LLM / 生成式AI / AIGC / 智能体 / Agent → 人工智能·AI 应用`；`芯片 / IC / 晶圆 / MCU / 车规 → 半导体`；`银行 / 券商 / 支付 / 互金 → 金融科技`；`AR / 眼镜 / XR / 空间计算 → 智能硬件`；`数仓 / BI / 指标中台 → 企业服务·数据平台` |
| `inferIndustryCategory(text)` | 由旧 `industry` 文本推断标准类目 id；推断不出落「未分类」 |
| `expandIndustryQuery(q)` | 查询词 → `{terms:[原词, 别名…], categories:[类目 id…]}` |
| `matchIndustry(c, q)` | 公司命中判定：标准类目 / 二级赛道 / 别名 / `industryAliases[]` / `industry` 原文 |

**检索逻辑**：先跑现有字面匹配（`allText()`），再叠加行业扩展匹配；因行业扩展命中的公司，在筛选行显示「按行业匹配：AI 应用 ← 大模型」并可一键清除，让用户知道为什么这家会出现。行业下拉按一级门类分组、显示每类公司数；卡片与详情头部显示标准类目 chip；编辑器里「下拉选标准类目 + 自由填展示文本 + 自定义别名」三者并存。

**与 `tags[]` 的关系（不要合并）**：`industryCategory` 是**受控、唯一、可聚合**的分类字段；`tags[]` 是**自由、多个、可跨类**的标记（B轮 / 重点跟进 / 16薪 / 大小周）。前者回答「属于哪个行业」，后者回答「有什么特征」。跨公司检索（§11-C11）依赖两者配合。

**兼容**：`industryCategory` / `industryAliases` 均为可选；旧数据缺类目时由 `industry` 推断兜底，`industry` 原文保留作展示，零迁移。词表落在 `company-store.js` 常量里，用户可在设置里追加自定义别名，不改动代码即可扩展。单测需覆盖别名扩展、旧文本推断、字面搜索不回归，并做变异验证。

### 10.5 连续融资情况可视化 `fundingRounds[]`

**问题**：融资调研现在是一条条文本（「2026 年完成 B 轮，累计约 3 亿元」），看不出「连续融了几轮、节奏多快、累计多少、最近一轮隔了多久」——而这几个恰恰是判断现金流与稳定性的关键。

字段：`{id, round, date, amount, currency, investors[], valuation, source:SourceRef, note}`；`round` 枚举：种子 / 天使 / Pre-A / A / A+ / B / B+ / C / C+ / D… / Pre-IPO / IPO / 战略融资 / 并购 / 未披露。

**可视化（原生内联 SVG，黑白灰，双视图可切换）**：
- **阶梯累计图**：横轴时间、纵轴累计融资额，每次融资一个台阶（step line + 浅灰填充），节点标轮次 / 金额 / 日期 / 领投方；一眼看出融资节奏与体量。
- **轮次时间线**：水平节点卡片（轮次 · 金额 · 日期 · 投资方 · 估值），节点间连线标注「间隔 N 个月」；适合轮次多、金额未披露的场景。
- 派生指标条：**累计融资额 / 轮次数 / 平均间隔 / 距最近一轮 N 个月 / 估值变化（若有）**。
- **与「风险与挑战」联动**：距最近一轮 >18 个月且「盈利情况」无正向资料时，图下方给出文字提示「距上一轮融资较久，建议核实现金流与盈利」（纯文字，不用颜色告警）。
- 口径：金额统一「万元 / 亿元」并标币种；**未披露金额不画 0**，节点显示「未披露」；空数据不画空图，显示「补充轮次数据以生成融资图」。
- **与 `research[]` 的关系**：保留原有融资文本叙述作为来源与背景，新增 `fundingRounds[]` 作为可视化数据源，二者通过 `linkedResearchIds` / `SourceRef` 关联，**不是替换**。简报可勾选「融资图」；多公司对比时融资节奏并排；完整度计算中「融资情况」有轮次数据标记为增强覆盖。

### 10.6 业务战略转型可视化 `strategyPhases[]`

**问题**：转型是「过程」，一段长文本只能描述某一个时间点，看不出「从哪转到哪、何时切换、哪几条业务线一起变」。

字段：`{id, phase, from, to, startAt, endAt, trigger, description, lanes:{product, revenue, customer}, status:'已发生|进行中|传闻', source:SourceRef}`。

**可视化（阶段演进图 / 泳道时间轴，原生 SVG + CSS）**：
- 上方**阶段横条**：每个阶段一个段落块（起止时间 + 阶段名 + 一句话定位），块之间用斜切 / 箭头分隔表示「转向」；转型点用竖线 + 菱形节点标注触发事件（如「2024：从硬件转向 AI Agent 平台」）。
- 下方**三条泳道**：主力产品 / 收入来源 / 目标客户，各自按阶段显示文本，三者在同一切点同时变化才真正体现「战略转型」，而非单纯改个口号。
- **转型前后并排对比**：一键切到「Before / After」两栏，对比业务口径、客户、收入模式。
- `status:'传闻'` 的阶段用**虚线**绘制，与风闻区规则一致；未证实不进正式图，不进对外简报。
- 与「竞品分析」「团队情况」「风险与挑战」联动：转型往往伴随团队换血与竞品变化，转型点可作为这些维度的时间锚点。
- 空态：只有文本描述时显示「标记阶段以生成转型图」，不伪造阶段。

**图片简报的技术注意**：SVG 图表进入 PNG 简报时，优先把内联 SVG 序列化为 `data:image/svg+xml` 再 `drawImage`，或直接按同一份数据用 Canvas 2D 重绘；**不要用 `foreignObject` / 外部字体**（html2canvas 会把它们渲染成空白）。这是「融资图 / 转型图能否出现在分享图片里」的关键约束。

## 十一、还需要补充什么（建议清单）

按「用户没想到但价值高」排序，分五组。前三项建议直接进 P0。

### A. 求职决策闭环（最建议补）

1. **我的判断 / 决策结论 `verdict`** ⭐：情报看完要落到一个结论。字段：推荐度（优先投 / 可投 / 观望 / 不投，**纯文字**）、关注点、风险红线、期望薪资与谈判底线、**待核实问题清单（面试要问什么）**、对应哪版简历。这是把「情报」变成「决策」的闭环，也是简报最该输出的第一段。**没有它，档案库只是资料堆**——这是目前方案最大的缺口。
2. **面试与面经 `interviews[]`** ⭐：轮次 / 形式 / 真题 / 面试官风格 / 反馈 / 时长 / offer 时效。原定位里「面试聊什么」就靠这块，现在完全空缺；面经也是自媒体链接里最高频的内容类型，应与 `links[]` 双向关联。
3. **待核实问题清单 `questions[]`**：把「不知道的」显式记下来（融资是否到账、团队是否扩张、加班真实情况、这个岗是不是新设），驱动下一次采集。完整度条只反映「六维有没有写」，问题清单反映「还差什么答案」，两者互补。

### B. 情报质量（不做会踩坑）

4. **信息新鲜度**：每条调研 / 薪资 / 福利显示「N 个月前」，>6 个月标「可能过期」；详情页顶部显示「主要资料时间范围」。融资、团队、薪资变动快，**过期情报比没有情报更危险**。
5. **来源冲突标记**：同维度多源说法不一致时并排展示（官网说弹性工作 / 脉脉说大小周），不覆盖、不自动判赢，冲突条目自动进「待核实」。这是情报库与笔记库的分水岭。
6. **统一来源模型 `SourceRef`**：相册 / 福利 / 风闻 / 薪资 / 链接 / 调研 / JD 七处都有来源，现在各写一套必然各自演化。抽象一次，全站复用，简报脚注自动汇总引用数。
7. **可信度分级扩展到全部条目**：不只八卦，正式调研也标「官方 / 媒体 / 员工口述 / 推测」，简报可按等级过滤。

### C. 结构与数据治理（本轮最大技术风险）

8. **图片存储策略必须在写第一行代码前拍板**（见 §10.2.1）：零后端 + 单 JSON + 5MB localStorage + `file://` 四者叠加，决定了图片不能进 JSON。建议本地媒体目录 + `serve.js` 静态托管 + 相对路径 + 单文件版降级外链 + 张数 / 体积上限 + 不参与 localStorage 同步。
9. **分享脱敏白名单**：图片简报要「离线分享出去」，就要定义可外发字段白名单（默认排除风闻、聊天截图、内部备注、私人判断），生成前确认清单 + 水印。
10. **变更留痕**：复用 N11 版本历史思路，`changes[]` 记录敏感字段（薪资 / 风闻 / verdict）的改动，误删可撤销。
11. **全局标签与跨公司检索**：内容多了要能回答「哪几家提到大小周 / 哪几家 16 薪 / 哪几家 2026 年融过资」。`tags[]` 需要一套受控词表 + 跨公司筛选，而不是完全自由输入。

### D. 采集与输出效率

12. **批量入口**：图片拖拽批量建相册、链接粘贴自动识别平台、PDF 报告按六维小标题切分导入（原 P1）、聊天截图 OCR 归档（依赖 AI Key，暂缓）。
13. **简报模板化**：一次配置三种输出 + 保存常用模板（见 §10.3-8）。
14. **跨板块回链增强**：从投递详情跳公司时带上「当时投的那份 JD」，公司侧自动高亮对应 JD 卡（现在只有一条回退条）。

### E. 明确不做（防止范围膨胀）

- 不自动爬取微信公众号 / 小红书 / 脉脉 / 知乎（反爬 + 合规 + 稳定性），只做粘贴录入 + 存档快照 + 已登录 Chrome 的 BOSS 聊天采集（已有能力）。
- 不接第三方实时薪资 API，薪资只做人工样本 + 可视化。
- 不做组织架构图编辑器 / 多人协作 / 云同步 / 客户端彩色图表库。
- 不恢复任何投递状态（铁律不变）。

### F. 本轮两条可视化引出后的通用建议（新增）

15. **把「时序事件」抽象成通用能力** ⭐：融资轮次、战略阶段、面试轮次、舆情事件、更新记录本质都是「带时间的事件序列」。建议抽象 `TimelineEvent {id, at, kind, label, detail, source:SourceRef}` + 一个通用横向时间轴渲染器，融资阶梯图 / 转型泳道图 / 舆情线 / 更新记录全部复用，避免每种图各写一套 SVG。
16. **图表必须能进三种输出**：所有 SVG 图提供「序列化为 data URI 再 `drawImage`」与「按同一份数据 Canvas 重绘」两条路径，保证 Markdown（转文字表）、PNG、打印里图表都不丢失；多公司对比并排展示区间 / 阶梯图时统一 X 轴与单位口径。
17. **录入时强制口径字典**：金额单位（万 / 亿）、币种、薪资周期（月薪 / 年薪 / 薪数）、日期粒度（年 / 月）在录入时下拉选择而非自由文本，否则图表不可比、聚合会算错。这条比「多画一张图」更能决定可视化能不能用。
