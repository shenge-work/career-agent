## 〇、一句话结论

把「个人作品集官网」纳入 CareerAgent，做成 **模板化 + 数据驱动 + 一键生成 + 一键 GitHub Pages 发布** 的闭环：
用户选模板 → 改内容/改布局（复用简历结构化数据）→ 一键生成静态网站 → 一键上传到 `shenge-work.github.io` 展示。
它与现有 N9「官网导出」、N1「主题模板系统」强相关，但**定位升维**——从"导出一次性的 HTML 文件"升级为"可持续维护、可换模板、可反复发布的个人作品集站点"。

## 一、背景与现状盘点

### 1.1 你现在的作品集（事实基线）

| 项 | 现状 |
|---|---|
| 源码位置 | `~/.local/share/TeleAgent/TeleAgent的工作空间/陈培胜-求职作品集/index.html`（**单文件 14KB**，TeleAgent 生成） |

**核心痛点**：现在的作品集是"一次生成、写死"的单文件。你想要的未来是——**有 N 套模板，随时换模板、改内容、改布局，一键重新生成、一键重新发布**。当前单文件形态无法支撑"模板复用 + 内容/样式分离"。

### 1.2 现有资产（可复用）

| 资产 | 位置 | 复用价值 |
|---|---|---|
| **Theme Schema** | `js/theme-templates.js`（v1） | 主题抽象范式可直接借鉴，但需从"简历 PDF 主题"扩展为"作品集官网主题" |
| **简历结构化数据** | `resumes.payload.data` | 官网内容的"个人简介/经历/项目/技能"可直接来自这里 |
| **渲染管线** | `src/server/render/` | 服务端生成 HTML 的能力可复用（vm 沙箱渲染 v1） |
| **N9 设计** | `docs/需求文档/N9-个人求职官网导出.md` | 已有"官网导出 + kpi-band + project-cards + 脱敏"的完整设计，本需求是它的升维 |

### 1.3 核心缺口

1. **无"作品集官网"模板体系**——N1 的 5 套主题是针对 A4 简历的，不适用于响应式作品集网站。
2. **无静态站生成器**——项目依赖里没有（见 `package.json`），N9 只设计到"导出 HTML 文件"。
3. **无 GitHub 发布能力**——没有 GitHub API 集成、没有凭证管理、没有"一键上传"。
4. **内容/布局/模板三者耦合**——现在单文件 index.html 里全混在一起，无法"只换模板不动内容"。

## 三、需求描述

### 3.1 核心概念：内容 / 布局 / 模板三者解耦

```
内容（Content）  ← 来自简历结构化数据（个人简介/经历/项目/技能/联系方式）
布局（Layout）   ← 板块顺序、板块显隐、板块内部结构（复用 N1 的 sections.order/visible）
模板（Template） ← 视觉风格（配色/字体/间距/组件样式），即"作品集官网主题"
```

用户操作对应：
- **改内容** → 编辑简历数据（已有编辑器能力）
- **改布局** → 拖拽板块顺序 / 开关板块（复用 N1 能力）
- **换模板** → 切换作品集官网模板（新能力）

### 3.2 模板系统（作品集官网模板，区别于简历模板）

**模板 Schema**（借鉴 N1 Theme Schema，但面向官网）：
```js
{
  id: 'minimal-portfolio',
  name: '极简作品集',
  preview: 'data:image/...',       // 模板缩略图
  // 官网专属：响应式断点 + 组件样式
  layout: { type: 'single-column' | 'split' | 'magazine' | 'brutalist' },
  colors: { bg, surface, ink, accent, muted },
  fonts: { heading, body, mono },
  components: {
    hero: { style: 'centered' | 'left' | 'split' },     // 首屏样式
    projectCard: { style: 'grid' | 'list' | 'masonry' }, // 项目卡片样式
    nav: { fixed: true, style: 'minimal' }
  }
}
```

**首批模板**（3~5 套，覆盖不同风格）：
1. 极简（minimal-portfolio）——单栏，大留白，黑白
2. 杂志（magazine）——多栏，强排版，适合文字型
3. 分屏（split）——左简介右项目，开发者友好
4. 粗野主义（brutalist）——高对比、大字体、无修饰（N9 已提）
5. 深色科技（dark-tech）——暗色 + 代码风，适合技术岗

### 3.3 静态站生成器

**选型原则**：零外部依赖、服务端可跑、输出纯静态、可换模板。

**方案**：**自研轻量生成器**（不引 Next.js/Astro 等重型框架，符合项目"零外部依赖"红线）：
- 输入：简历结构化数据 + 模板 + 布局配置
- 输出：一个完整的静态站目录（`index.html` + `assets/`），纯 HTML/CSS/JS，可被 GitHub Pages 直接托管
- 实现：复用 `src/server/render/` 的渲染思路——模板是"数据 + 模板函数 → HTML 字符串"，在服务端生成

> 备选：若未来模板复杂到需要组件化，再评估引入 Astro（静态站生成器），但本轮先自研轻量版。

### 3.4 一键 GitHub Pages 发布

**这是本需求最需要仔细设计的部分（涉及凭证安全）**。

**发布目标**：用户站点 `shenge-work.github.io`（或任意 `https://<user>.github.io`）。

**发布机制（三选一，见 §八评审）**：

| 方案 | 原理 | 凭证 | 优点 | 缺点 |
|---|---|---|---|---|
| A. GitHub API 直接提交 | 用 PAT 调 `PUT /repos/:owner/:repo/contents/:path` 覆盖文件 | **PAT（个人访问令牌）** | 最简单，一条链路 | PAT 需存服务端，安全敏感 |
| B. git CLI 推送 | 本地生成 → `git clone/pull` 目标仓库 → commit → push | **本地 git 凭证**（已配置的 credential helper） | 复用现有 git 环境，令牌不落盘 | 依赖本地 git 配置，需 clone 仓库 |
| C. GitHub Actions 自动部署 | 把生成的站 push 到源仓库，触发 Actions 构建部署 | 同 B | 标准化，CI 可见 | 重，需配 workflow |

**推荐：方案 B（git CLI 推送）**，理由见 §八。核心设计：
- 发布前校验目标仓库是 `<user>.github.io` 格式（用户站点），或明确配置的项目站点
- 生成静态站 → 写入本地 staging 目录 → `git` 提交到目标仓库 → push
- 凭证走**本地已配置的 git credential helper**，令牌不落盘、不出本机

### 3.5 交互流程

```
作品集页（#/portfolio）
  ├── 选模板（模板画廊，含缩略图）
  ├── 改内容（复用简历数据编辑，或独立作品集数据）
  ├── 改布局（拖拽板块 / 开关板块）
  ├── 预览（实时渲染，响应式预览：桌面/平板/手机）
  ├── 生成（一键生成静态站到本地目录）
  └── 发布（一键上传 GitHub Pages，显示发布结果 + 公网 URL）
```

## 四、数据结构

### 4.1 新增表（作品集配置）

```typescript
/** 个人作品集站点：一次配置，可反复生成/发布。 */
export const portfolios = pgTable(
  'portfolios',
  {
    id: text('id').notNull(),
    userId: uuid('user_id').notNull().references(() => users.id, { onDelete: 'cascade' }),
    title: text('title').notNull(),
    /** 关联的简历（内容来源），可为空（独立作品集数据）。 */
    resumeId: text('resume_id'),
    /** 当前模板 id（模板定义在代码内置模板库，这里只存引用）。 */
    templateId: text('template_id').notNull(),
    /** 布局配置：板块顺序/显隐/自定义板块。 */
    layout: jsonb('layout').$type<Record<string, unknown>>().notNull().default(sql`'{}'::jsonb`),
    /** 发布配置：目标仓库、分支、最近发布信息。 */
    deploy: jsonb('deploy').$type<{
      repo: string;          // 如 shenge-work.github.io
      branch: string;        // 默认 main
      lastPublishedAt: number;
      lastUrl: string;       // 公网 URL
    } | null>(),
    /** 作品集专属内容（kpi-band / project-cards 等官网板块数据）。 */
    payload: jsonb('payload').$type<Record<string, unknown>>().notNull().default(sql`'{}'::jsonb`),
    createdAt: createdAt(),
    updatedAt: updatedAt(),
  },
  (t) => [
    primaryKey({ columns: [t.userId, t.id] }),
    index('portfolios_user_idx').on(t.userId),
  ]
);
```

### 4.2 模板库（代码内置，不落库）

模板定义放代码（`src/server/portfolio/templates/`），`templateId` 只是引用。模板是纯函数
`(data, layout) => htmlString`，可单测、可扩展。

`drizzle/0007_portfolios.sql` —— 建 `portfolios` 表（PGlite 单进程铁律：迁移前停 dev）。

## 五、工程护栏

1. **每张新表带 `user_id`**，查询走 `TenantDb.forUser(userId)`，跨用户返 404（铁律）。
2. **凭证安全（发布最关键）**：发布走**本地 git credential helper**，PAT/令牌**永不落盘、不出本机**；
   服务端不存任何 GitHub 凭证。若用户走 PAT 方案，需显式提示"令牌仅本次使用，不保存"。
3. **脱敏**：公开部署默认隐藏手机号/住址/身份证（沿用 N9 F5），发布前显式提示。
4. **内容真实**：官网数字/公司名来自录入数据，模板只改视觉不改内容，不做 AI 编造。
5. **迁移走 drizzle 手写 SQL**，测试先行（`npm test` 权威 + 变异测试）。
6. **零外部依赖**：静态站生成器自研，不引 Astro/Next.js；GitHub 发布用 git CLI，不引 octokit 等 SDK。
