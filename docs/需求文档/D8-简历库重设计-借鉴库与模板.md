# D8 简历库重设计——借鉴库与一键换模板

## 一、背景与现状

用户对简历库板块的新定位（2026-11-04 原话归纳）：**本地服务器部署、有数据库、未来有本地对象存储**，
简历库将承担三个新职责：

1. **上传他人的简历**——供参考、学习、阅读（借鉴库）；
2. **参考他人的简历模板**——看到好排版能记下来、用起来；
3. **一键换模板**——自己的简历在多套视觉主题间秒切。

当前简历库（`src/web/pages/Library.tsx`）能力：列表、新建、母版标记、删除、版本历史
（手动快照 + 自动留痕 + 恢复）。**没有**：上传、借鉴、模板概念；投递记录
（`tracker.payload`）也没有简历引用与面试准备材料。

### 竞品参照

| 竞品 | 做对了什么 | 本项目取舍 |
|---|---|---|
| **Reactive Resume** ★43.2k | 15 套模板一键切换（结构化样式规则对象）；dashboard 缩略图 | 模板切换的**数据模型**照搬其思想（N1 已有 Theme Schema）；缩略图归 N5 另行排期 |
| **Magic Resume** | 19 套模板 + 完全自定义颜色/字体/间距 | 内置 5 套够用；微调列第二批 |
| **OpenResume** | PDF 解析导入（别人简历 → 结构化数据） | 借鉴库第一批只做**原文件保存 + 文本提取 + 人工标注**，不做结构化反推（PII 与成本考虑） |
| **v1 本项目**（git `ae71f43`） | `js/theme-templates.js`：Theme Schema + 5 套主题（classic / modern / elegant / warm / minimal）+ `applyTheme` 物化方案 | **直接移植**——这是本项目自己的成熟资产，从 git 历史恢复后服务端化 |

## 二、定位与边界（设计铁律）

**一句话定位**：简历库 =「我的简历」+「别人的好简历」两个物理隔离的子域，加一条把
「别人的好排版」变成「我的一键换模板」的通路。

五条不可破的契约：

1. **物理隔离**：借鉴简历独立新表 `reference_resumes`，与 `resumes` 永不混存。借鉴简历
   **永远不进**投递锁定、渲染管线、分享授权、PDF 导出、版本历史——schema 级杜绝误用，
   而不是靠 UI 约定。
2. **借鉴库只进不出**：可上传、可阅读、可标注；**不提供**借鉴简历的导出 / 分享 / 转投递
   （他人简历含 PII，仅本人本机参考）。
3. **换模板只改样式不改内容**：切换主题不触碰 `sections` 内容、不触碰血缘字段
   （`parentId/kind/jobId`）；有内容的板块被主题隐藏时提示「内容保留，可随时恢复」。
4. **逐字稿挂投递维度**（D7 v3 修订已拍板方向）：自我介绍 / 项目讲述 / 常见问答属于
   「这次投递的面试准备」，落 `tracker.payload.prep`，`tracker_id + resume_id` 双引用；
   公司档案 `interviews[]` 存「该公司怎么面人」的面经情报——**公司存「他们怎么面」，
   投递存「我怎么准备」**，两者互补不重复。
5. **视觉铁律**：全站严格黑 / 白 / 灰（D7 同款令牌），主题只作用于「简历纸张」本身
   （v1 N1 的职责边界：外壳明暗 vs 纸张风格），不新增任何彩色 UI。

### 用户场景

- **刷到一份好简历**（朋友内推的 PDF / 网上大佬的作品）→ 拖进借鉴库 → 标注「这个项目
  描述的动词用得好」「这个双栏布局清爽」→ 下次改简历时翻出来对照。
- **投不同风格的公司**（外企保守 vs 创业公司新潮）→ 同一份内容一键切换 classic /
  modern 主题，导出两版 PDF。
- **快面试了** → 打开该投递的「面试准备」区，过一遍自我介绍逐字稿和预判问答。
- **误换模板** → 版本历史里「换模板前自动快照」一键恢复。

## 三、总体设计：三个子域 + 一条挂载线

```
┌────────────────────────────────────────────────────────────┐
│  子域 A · 我的简历库（现有 resumes 升级）                      │
│  列表 / 新建 / 母版 / 版本历史（已有）+ 换模板入口（新增）        │
└────────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────────┐
│  子域 B · 借鉴库（新实体 reference_resumes，物理隔离）           │
│  上传（PDF/图片/粘贴文本）→ 阅读 → 借鉴标注 → 标签/笔记          │
└────────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────────┐
│  子域 C · 模板系统（N1 服务端化）                                │
│  Theme Schema + 5 套内置主题（v1 移植）+ 服务端渲染管线应用        │
│  + 前端一键切换（写 payload.data.theme → 预览刷新）             │
└────────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────────┐
│  挂载线 · 面试逐字稿（挂投递维度，D7 v3 决策）                   │
│  tracker.payload 增补 resumeId + prep{...}，投递详情新增        │
│  「面试准备」区（不在简历库 / 公司档案新增任何字段）              │
└────────────────────────────────────────────────────────────┘
```

B 与 C 的衔接（「参考他人模板」的落地方式，第一批取最小闭环）：借鉴库的标注 `reason`
自由记录排版借鉴点，另提供「这份排版接近哪套主题」的**人工标签**（5 选 1 下拉，写入
`payload.templateAffinity`），点一下即可跳到我的简历库去应用同款主题——**不做**从他人
简历图片自动反推样式参数（见 §十一 非目标）。

## 四、数据模型与 API

### 4.1 借鉴库新表 `reference_resumes`（迁移 `drizzle/0005_create_references.sql`）

沿用 `resumes` / `companies` 的行级隔离模式（`user_id` 外键 + 主键含 userId）：

```ts
export const referenceResumes = pgTable('reference_resumes', {
  id: text('id').notNull(),
  userId: uuid('user_id').notNull().references(() => users.id, { onDelete: 'cascade' }),
  payload: jsonb('payload').$type<Record<string, unknown>>().notNull(),
  createdAt: createdAt(),
  updatedAt: updatedAt(),
}, (t) => [primaryKey({ columns: [t.userId, t.id] }), index('reference_user_idx').on(t.userId)]);
```

`payload` 结构（jsonb，全部可选字段由前端 `normalizeReference()` 补全缺省，旧数据零迁移）：

```jsonc
{
  "title": "张三 · 某大厂 AI 平台 · 高级工程师",   // 必填，唯一必填项
  "sourceType": "pdf" | "image" | "text",
  "fileKey": "references/abc123.pdf",      // 服务端媒体目录相对路径（文本粘贴可空）
  "fileName": "张三简历.pdf",                // 原文件名（下载/回显用）
  "text": "提取或粘贴的正文……",             // PDF 自动提取 / 手动粘贴；图片为空
  "highlights": [                           // 借鉴标注（核心）
    { "id": "h1", "quote": "主导…从0到1…", "reason": "动词+规模+结果三段式", "page": 1 }
  ],
  "notes": "整体节奏紧凑，技能区放最后",
  "tags": ["双栏", "量化充分", "大厂风"],
  "templateAffinity": "modern",             // 人工标注：排版接近哪套内置主题（5 选 1，可空）
  "fromCompanyId": null,                    // 可选：关联公司档案 id（跨板块只读引用）
  "savedAt": 1762300000000
}
```

**存储落点**：原文件存服务端媒体目录 `assets/media/<tenant>/references/`（按账号分目录），
未来整体迁本地对象存储（ROADMAP 已列项，D7 公司相册同一套）。上传约束：类型白名单
`pdf/png/jpg/jpeg/webp/txt`，单文件 ≤ 20MB。

### 4.2 模板系统（无新表、无新 API）

- **主题数据**：`src/web/theme-templates.ts`（纯函数模块，从 git `ae71f43` 恢复
  `js/theme-templates.js` 后改写为 TS）：Theme Schema + 5 套主题 + `resolvePalette` /
  `getTheme` / `ensureTheme`。前端画廊与渲染层共用。
- **主题持久化**：`resumes.payload.data.theme = { id, overrides? }`（v1 N1 同款落点，
  迁移数据天然兼容——无 theme 字段 = classic）。
- **服务端应用**：`legacy-renderer.ts` 渲染前把 theme **物化**进渲染全局态
  （`currentFonts` / `currentSpacing` / `pageMargins` + `applyPaletteToEl` 内联调色板），
  即 v1 `app.js#applyTheme` 的服务端化；预览、双版 PDF、分享页三条渲染路径一次接入。
- **前端交互**：无独立 API——切换 = `PUT /api/resumes/:id`（写 `data.theme`）→
  版本自动快照 → 预览刷新（现有 `GET :id/preview`）。

### 4.3 逐字稿（无新表、无新 API）

`tracker.payload` 增补两个字段（向后兼容，旧记录缺省补全）：

```jsonc
{
  "company": "…", "position": "…", "platform": "…", "status": "…", "chat": [],   // 已有
  "resumeId": "res_xxx",        // 新增：该投递锁定的简历（也为后续 JD 派生血缘铺路）
  "prep": {                     // 新增：面试准备材料
    "selfIntro": "面试官您好，我是……",
    "projects": [ { "title": "comein.cn", "script": "这个项目我负责……" } ],
    "qa": [ { "q": "为什么离开上一家？", "a": "……" } ]
  }
}
```

落 payload 而非新表的理由：与投递 1:1、量级小（纯文本）、无需跨投递检索；与 D7
「数据落 payload、无需建新表」原则一致。`resumeId` 指向的简历被删除时优雅降级
（显示「原简历已删除」占位，不报错、不级联删逐字稿）。

### 4.4 API 清单

| 方法 | 路径 | 说明 |
|---|---|---|
| GET / POST | `/api/references` | 借鉴库列表 / 新建（`{ title, sourceType, text? }`） |
| GET / PUT / DELETE | `/api/references/:id` | 详情 / 更新（标注、笔记、标签、affinity）/ 删除（连带删媒体文件） |
| POST | `/api/references/:id/file` | 上传原文件（multipart，白名单 + 20MB），写 `fileKey` |
| GET | `/api/media/:tenant/references/:file` | 服务端托管只读回传（行级校验：仅本租户可读自己的） |
| — | 模板 / 逐字稿 | 无新增：分别走 `PUT /api/resumes/:id` 与 `PUT /api/tracker/:id` |

## 五、借鉴库交互规格

- **上传三通道**：拖拽 / 点击上传（PDF、图片）；大文本直接粘贴（sourceType=text）。
  PDF 上传后服务端用 `pdf-parse`（纯 JS，零系统依赖）自动提取全文存 `text`，失败不阻塞
  ——降级为「请手动粘贴正文」。图片第一批**不做 OCR**（见 §十一），原文件保存后对着图读。
- **列表**：与简历库同款卡片（标题、来源类型 chip、标签、标注数、更新时间）；
  搜索（标题 / 标签 / 正文 / 标注）；复用 D7 `industryCategory` 词表做行业筛选（可选）。
- **阅读视图**：左侧原文（PDF 提取文本 / 图片预览），右侧标注与笔记；选中一段文本
  →「＋ 借鉴标注」→ 填 reason 入库。
- **模板参考标签**：`templateAffinity` 5 选 1 下拉（接近 classic / modern / elegant /
  warm / minimal）+ 「去我的简历库应用同款」跳转按钮。
- **空态 / 错误**：无文件时提示拖拽区；上传超限 / 类型不符走既有 `alert` 模式。

## 六、一键换模板交互规格

- **入口**：库页详情面板 + 编辑页头部，同一组件 `<ThemeGallery>`：5 张主题卡
  （名称 + 一句话风格描述 + 当前主题高亮），点卡片即换。
- **切换语义**：`PUT` 写 `data.theme`；服务端先自动存版本
  `kind:'auto'`、`label:'换模板前自动快照（HH:mm:ss）'` 再落盘——**误切可从版本历史一键恢复**
  （v2 暂无编辑器级撤销栈，用既有版本机制承接「可撤销」要求，ROADMAP 撤销栈落地后接入）。
- **内容零触碰**：切换前后 `sections` 深比较必须相等（验收 #3）；隐藏有内容的板块前弹确认
  「该板块有 N 条内容，隐藏后不会删除，可随时恢复」。
- **微调（overrides）**：7 色 accent 面板等 v1 能力列**第二批**，第一批只做 5 套整切。

## 七、面试逐字稿交互规格（投递详情 · 面试准备区）

- 投递详情面板新增「面试准备」折叠区：自我介绍（多行）、项目逐字稿（标题 + 正文，可多条）、
  预判问答（Q/A，可多条），全部就地编辑、失焦保存。
- 顶部显示「所用简历：〈标题〉」+ 切换按钮（写 `resumeId`）——同一处为 JD 派生血缘铺路。
- 公司侧 `interviews[]`（D7 第二批）提供「他们怎么面」的面经；本区显示「我怎么准备」，
  两者在 UI 上互链（投递详情 ↔ 公司档案）但不共字段。

## 八、实施批次

- **第一批（建议本批落地）**：
  ① 借鉴库表 + 上传三通道 + 阅读视图 + 借鉴标注 + 模板参考标签；
  ② `theme-templates.ts` 移植 + 服务端渲染管线物化 + `<ThemeGallery>` 一键换模板
  （预览 / 双版 PDF / 分享页三路径）；
  ③ `tracker.payload` 增补 `resumeId + prep` + 投递详情「面试准备」区。
- **第二批**：主题微调 overrides（7 色 / 字号 / 间距）、图片 OCR（借鉴库）、
  借鉴简历 ↔ 公司档案 `fromCompanyId` 联动、缩略图仪表盘（N5）联动、AI 借鉴分析
  （喂 AI 前需显式开关，他人 PII 不默认进任何 AI 请求）。

## 九、验收标准（可测试的量化指标）

1. 上传 PDF / 图片 / 粘贴文本各 1 份 → 列表可见；PDF 的 `text` 自动提取非空；标注添加后
   刷新仍在（PG 落库验证）。
2. **隔离断言**：`/api/references` 的任何 id 在「我的简历库」列表、投递锁定简历选择器、
   分享授权列表中零出现（API 层字符串级断言）。
3. **换模板零丢失**：切换 5 套主题前后 `payload.data.sections` 深比较相等；默认主题
   渲染结果与当前基线**像素级一致**（既有渲染快照测试不红）。
4. 换模板后版本历史出现「换模板前自动快照」，`POST …/restore` 可完整回到换前样式与内容。
5. 投递详情编辑逐字稿三区并保存 → 刷新仍在；`resumeId` 指向已删简历时显示占位不报错。
6. 账号 B 访问账号 A 的借鉴文件 → 404（媒体路由租户校验）。
7. 换主题后双版 PDF 仍满足既有 2 页 / 矢量可选中契约；控制台零报错。
8. 变异测试：删除渲染管线 theme 物化步骤 → 主题断言转红；删除恢复前自动快照 → 恢复链路断言转红。

## 十、工程护栏

1. **PGlite 单进程铁律**：`db:migrate`（`0005_create_references.sql`）前必须停 dev。
2. 渲染层「读常量 → 读主题」是破坏性改动：默认主题必须与现网**像素级一致**，跑全部既有
   渲染 / PDF 测试 + 变异测试后再合入。
3. 新模块遵循现有分层：借鉴库 `references` 走 `business` 模块（controller + service +
   tenant-db 方法），前端页面 `src/web/pages/References.tsx`，样式追加既有灰阶体系。
4. 上传安全：类型白名单 + 大小上限 + 文件名清洗；媒体路由做租户校验。
5. 他人简历 PII：仅本机存储、不进任何远程调用；借鉴库不提供导出/分享（铁律 2）。
6. 测试数据用虚构姓名（延续既有 PII 隔离约定）。

## 十一、非目标

- **不做**从他人简历图片自动反推样式参数（「一键复制他的排版」）——视觉→结构化参数的
  逆向不可靠，且易诱导抄袭；借鉴走「人工标注 + 主题 affinity」。
- **不做**借鉴简历的结构化解析入库（OpenResume 路线）——他人数据只读参考，不入编辑管线。
- **不做**借鉴库的导出 / 分享 / 下载原文件以外的任何出站通道。
- **不做**在线主题市场 / 用户自定义 CSS 文件（延续 N1 非目标）。
- 第一批**不做** OCR、不做 AI 分析（后者永远需要显式开关）。

## 十二、待拍板决策点

| # | 决策 | 推荐 | 理由 |
|---|---|---|---|
| 1 | 借鉴库存储：独立新表 vs `resumes` 加 kind 字段 | **独立新表** | 物理隔离铁律：schema 级杜绝借鉴简历流入投递/渲染/分享管线 |
| 2 | 换模板入口：编辑页内嵌画廊 vs 独立 `#/templates` 页 vs 两处 | **库页详情 + 编辑页两处同组件** | v2 无多页面模板市场诉求，内嵌最短路径 |
| 3 | 主题微调（overrides）是否进第一批 | **不进** | 控制第一批范围；5 套整切已覆盖主诉求 |
| 4 | 逐字稿：tracker payload vs 新表 | **payload jsonb** | 1:1 强绑定、纯文本量小、零迁移 |
