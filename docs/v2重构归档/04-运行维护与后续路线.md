> ⚠️ **P6 更新（2026-11-04）**：v2 已上移为**仓库根主目录**（v1 退役、飞书同步拆除），本文命令均在仓库根执行；测试基线改为 **113 通过 / 3 跳过（共 116）**，迁移已应用至 `0004_drop_sync`。

## 1. 首启与常用命令

在**仓库根**执行（2026-11-04 起 v2 即主目录，Node >= 22.12，依赖已 `npm install`）：

```bash
npm run db:migrate                       # 1. 应用 drizzle/*.sql（停 dev 后执行更安全）
npm run seed:user -- --email me@local.test --password '<强密码>' --role admin   # 2. 建号
npm run dev                              # 3. Vite 5173 + NestJS 3000
```

浏览器打开 `http://127.0.0.1:5173`。若已有 `pgdata/`，可跳过 1、2 直接 `dev`；但演示口令必须按 §6 处理。

| 命令 | 用途 |
| --- | --- |
| `npm run dev` / `dev:server` / `dev:web` | 全链路 / 只起 API / 只起前端 |
| `npm test` / `test:watch` | Vitest 全量 / 监听 |
| `npm run build` | `tsc -p tsconfig.json` + `vite build`（产物 `dist-server/`、`dist-web/`） |
| `npm start` | 跑编译后的 `dist-server/server/main.js` |
| `npm run db:migrate` | 顺序应用 `drizzle/*.sql`，`_migrations` 记录 |
| `npm run db:generate` | drizzle-kit 生成 DDL 到 `drizzle/generated/`，仅用于比对漂移 |
| `npm run import:v1` | 从旧 `data/` 导入（自动备份、单事务、读回校验） |
| `npm run import:v1 -- --dry-run` | 只校验不写库不备份 |
| `npm run import:v1 -- --force` | 覆盖已存在记录（默认跳过） |
| `npm run seed:user -- --email ... --password ... --role admin\|member` | CLI 建号 |

`import:v1` 另支持 `--email`（导入到指定账号）、`--source`（源数据目录）、`--pgdata`、`--backup-dir`。

## 2. 日常操作要点

- **登录 / 账号**：只有 admin 能进 `/api/users` 建号、停用账号；停用后 `SessionGuard` 立即拒绝该用户的会话。
- **编辑简历**：`#/editor/:id`，右栏改动停 800ms 自动保存，左预览自动刷新。原始 JSON 兜底入口可改任意字段；保存 payload 必须带 `savedAt`。
- **导出**：矢量版文字可选中、体积小，推荐；图片版按 v1 分页契约精确分页、体积大、文字不可选。两者都要求本机有 headless Chrome。
- **AI**：`#/account` 填 `baseUrl` / `apiKey` / `models.fast` 等，先「测试连接」再保存；Key 不会回显（只显示 `hasApiKey`）；`#/ai` 可流式试用。也可用本地 Ollama（http 仅放行回环）。「停用配置」写一行空配置，之后不再回退到 v1 `ai.config.json`。
- **BOSS 采集**：先完全退出 Chrome（Cmd+Q），用登录过 BOSS 的默认档案启动调试端口（`tools/start-chrome-debug.sh`，默认 9222），再在投递详情页填端口点「从 BOSS 采集聊天」。结果直接入库、重复采集不翻倍；无端口时返回明确 hint。
- **飞书同步**：已于 P6 **整体拆除**（模块、三张表、豁免、前端面板全部移除），不再提供；版本能力由 PG 本地版本历史承接（见 [03 §13](./03-实施与验收全记录.md)）。
- **数据**：所有业务数据在仓库根 `pgdata/`（PGlite）；旧 `data/` 是 v1 迁移前原始数据的只读备份（gitignored，保留作底）；`backups/` 存迁移时快照。

## 3. PGlite 单进程铁律（最易踩的运维坑）

`pgdata` 是**进程内单连接**数据库，同一时刻只能由一个进程持有。以下操作前必须停 `npm run dev`：

- `npm run db:migrate`（新迁移落库）
- `npm run import:v1`
- 任何 `new PGlite('./pgdata')` 的核查 / 修复脚本

标准流程：

```bash
# 1) 停 dev（找到 3000 / 5173 的进程再 kill，或用后台任务的停止能力）
lsof -nP -iTCP:3000 -iTCP:5173 -sTCP:LISTEN
# 2) 确认端口释放后执行写库命令
npm run db:migrate
# 3) 校验（只读探针也要在 dev 停止期间做）
# 4) 重启
npm run dev
curl -s --noproxy '*' -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5173/
```

本地 HTTP 联调一律用 `127.0.0.1`（不要用 localhost）并清掉代理环境变量（`env -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY ...`，curl 加 `--noproxy '*'`），否则请求会被代理劫持。

## 4. 备份与恢复

- v1 源数据备份：`backups/<时间戳>/source/` + `manifest.json`（逐文件 sha256）。这是迁移前的只读快照。
- **运行数据备份**：停 dev 后整体复制仓库根 `pgdata/` 目录（PGlite 落盘目录），并记录当时 `_migrations` 内容。恢复 = 停 dev → 用备份目录覆盖 `pgdata/` → 重启。
- 不要只复制单个文件；PGlite 的数据目录是整体一致的。
- `pgdata/` / `backups/` / `dist*/` / `data/` 均 gitignored，换机器必须显式拷贝，仓库里没有这些数据。

## 5. P5：切换到真 PostgreSQL（尚未实施，步骤供执行时参考）

之所以能「平替」，是因为 schema、迁移 SQL、查询全部用 PostgreSQL 方言，PGlite 实测与 PG 18 一致。切换预计只动数据驱动层：

1. 有管理员权限的机器上装 PG 18（`brew install postgresql@18 && brew services start postgresql@18`），建库与账号。
2. 仓库根增加 `pg` 依赖与 `DATABASE_URL` 配置；`src/server/db/client.ts` 把 `drizzle-orm/pglite` 换成 `drizzle-orm/node-postgres`（`TenantDb` / schema / 控制器不动）。
3. 用同一套 `drizzle/*.sql` 在真 PG 上跑 `db:migrate`（方言一致，应可原样复用）；补一条对照测试验证 `jsonb` / `ON CONFLICT` / 复合主键行为。
4. 数据搬迁：停 v2 → 从 `pgdata` 导出为 JSON（`import-v1` 的解析/校验逻辑可复用）→ 在新库重放导入并做语义比对 → 双跑一段时间再下线 PGlite。
5. 回归 `npm test`、`npm run build`、真实 HTTP 与 PDF 导出。

**注意**：当前 `client.ts` 只认 `PGDATA`，`DATABASE_URL` 与 `pg` 依赖都还不存在；上面是计划，不是已完成的代码路径。

## 7. 常见故障速查

| 现象 | 优先检查 |
| --- | --- |
| 迁移 / 核查脚本报错或数据异常 | dev 是否还占着 `pgdata`（§3 单进程铁律） |
| 所有接口 403 | Host/Origin 是否回环；是否误用 `localhost` 或被代理改写头 |
| 未登录 401 后前端循环跳转 | `api.ts` 只对非 `/auth/` 的 401 广播，`/auth/me` 必须排除 |
| DELETE / GET 返回 400 | 是否给无 body 的请求带了 `Content-Type: application/json`（Fastify 直接拒） |
| POST 探测接口返回 201 | 是否漏了 `@HttpCode(200)` |
| 「停用 AI 配置」点了没反应 | 见上一条；已修复并验过 |
| AI 报上游地址不合法 | `validateBaseUrl` 只放行 https 公网 / http 回环；检查字面私有 IP、userinfo、query |
| 同步上报 / OAuth 回调相关故障 | 已随 P6 飞书拆除而消失：sync 端点现在统一 404，属预期行为 |
| SSE 卡住不返回 | 是否走了 `reply.hijack()`；Vite 代理是否指向 3000；上游超时（`timeoutMs`） |
| 采集无结果 | Chrome 是否以调试端口启动、端口是否与 `CDP_PORT` 一致；`GET /api/collect/status` 看脚本可用性 |
| 导出 PDF 501 | 本机是否有 headless Chrome；`CHROME_PATH` 可指定 |
| 图片版卡住 / CDP 超时 | 是否用了真 iframe、大 base64 回传、未桩掉 `confirm`（P4b 三个坑） |
| 预览里出现他人数据或样式错乱 | vm context 是否每次新建；`ctx.window = ctx`；`mmNum` 空值回退 |
| CDP 里改动「没生效」 | 先 navigate 到 `about:blank` 再进目标 URL，强制重载资源 |
| React 受控 input 脚本改值无效 | 用 native value setter + `input` 事件，按 label 精确定位 |

更完整的根因与修复记录见 [03 §9](./03-实施与验收全记录.md)。
