## 6. P4b · 图片版 PDF 分页契约

- Spike 确认链路：`makeCaptureClone → html2canvas → RB.computePageBreaks(cap.clone) → jsPDF 逐页 drawImage`；因需量真实 DOM，不能放进服务端 vm，改为「生成导出专用页 + headless Chrome CDP 真跑」。
- `legacy-export-html.ts`：内联 v1 CSS/JS bundle + 本地 vendor、DOM 哑元素兜底、`confirm/alert` 桩、payload `</script>` 转义、CSP `connect-src 'none'`；driver 自动 `applyImported → exportPDF → downloadPDFNow()`，并 monkey-patch `RB.getPageMetrics` / `computePageBreaks` 记录 `rootIsClone / rootW / rootH / breaks`。
- `image-pdf.service.ts`：`--remote-debugging-port=0` + `DevToolsActivePort` 取端口、Node 22 内置 WebSocket、`Browser.setDownloadBehavior`、轮询 `window.__RESULT__` 与下载文件、超时与 SIGKILL / 临时目录收尾；返回 `{ buffer, pages, pagesLabel, live, paging }`。
- API：`GET :id/pdf?mode=image`、默认矢量不变、`GET :id/export-page`。前端拆成「矢量 PDF（推荐，文字可选中）」「图片版 PDF（精确分页）」两个按钮。
- 验收：65 通过 / 3 跳过；三组变异有效（去转义 → XSS 红、去 DOM 兜底 → 结构红、去分页探针 → 契约红）；正式代码实测 **4,225,003 B / `%PDF-1.3` / 3 页**，契约 `rootIsClone=true`、克隆与预览同为 `794×2727`、断点 `[0, 1017, 2033, 2621]`；HTTP：矢量 987 KB vs 图片版 4.2 MB、导出页 869 KB、401/404 正确；CDP：三按钮齐全、iframe `.resume` 且 0 script、点图片版下载中文名 PDF 4.2 MB、运行时错误与非预期 4xx 均 0。

## 8. P2b 第二期 · 飞书 OAuth / 版本同步 / Device Flow 注册

> ⚠️ **P6 后续注（2026-11-04）**：飞书同步能力已在本轮主目录切换中**整体拆除**（用户拍板「飞书扫码功能不要了，数据全在 PG」），三张 sync 表由 `0004_drop_sync.sql` 删除，回环守卫豁免同步回退。本节保留为过程存档，勿据此认为飞书链路仍存在；版本能力由 PG 本地版本历史承接（见 §13）。

- **范围**：把 v1 `tools/serve.js` 的 `sync` / `feishu` 两组路由与 `feishu-sync.js` / `feishu-oauth.js` / `feishu-register.js` 三个模块迁到 v2 NestJS；v1 源码零改动（8000 端口的 v1 同步链路照常独立可用）。
- **凭证按账号落库（`0003_sync.sql`，停 dev 后 `db:migrate` 已应用到 pgdata）**：
  - `sync_configs(user_id PK)`：应用身份配置，`app_secret` 只留服务端，GET 一律脱敏（`hasSecret`）；
  - `sync_oauth(user_id PK)`：扫码授权的用户身份凭证，毫秒时间戳有效期（沿用 v1 `Date.now()` 语义）；
  - `sync_state(user_id, resume_id)`：每份简历 × 认证模式的飞书锚点 —— **v1 的 `stateKeyFor()` 加 `_user` 后缀分键隔离在 v2 直接落成不同列**（`document_id/file_token` 与 `user_document_id/user_file_token`），语义等价。
  - 回退语义：DB 无行时**只读**回退 v1 `sync.config.json`（`SYNC_CONFIG_FILE` 可覆盖）；**OAuth 凭证不回退 v1 文件**（两套系统的云盘锚点各管各的，复用 user token 会写同一个文件互相打架）；DELETE 写空行 = 显式停用，绝不回退（与 AI 停用同语义）。
- **模块结构**（`src/server/sync/`）：`sync-config.ts` 纯函数（脱敏 / 归一化 / `buildAuthorizeUrl` / `encodeAddons` / `mapPollStatus` / `buildProbeDefaults` / 回调页，v1 逻辑逐条移植）+ `feishu-client.ts` 底层 HTTP（**transport 可注入 `SYNC_HTTP`**，默认 global fetch，测试注桩即可离线覆盖全链路）+ `sync.service.ts` 编排 + `register-session.store.ts` Device Flow 会话 + `sync.controller.ts` 14 端点。
- **与 v1 的契约差异（迁移注意）**：
  - 上报改为 `POST /api/sync/report/:resumeId`——简历**从服务端 DB 读**，不再信任前端 POST 的整份 payload；
  - probe 探测的默认项**直接落库**（v1 只回显给表单，用户还得再点一次保存）；
  - Device Flow 注册成功后**凭证 + probe 默认项一并落库**（v1 只落凭证）；
  - OAuth 回调必须携带 start 时签发的 state（v1 不校验 state），state→userId 映射是匿名回调找回账号的唯一依据，10 分钟过期；
  - 回调端口从 v1 的 8000 变为 v2 的 3000（`PORT` 跟随），**需在飞书开放平台「重定向 URL」追加登记**。
- **安全**：回环守卫为回调路径开了一个**精确前缀豁免**（`/api/feishu/oauth/callback`，仅 GET、Host 仍须回环，`security.ts CROSS_SITE_ALLOWED_PREFIXES`）——飞书授权页是浏览器 302 跨站抵达，`Sec-Fetch-Site: cross-site` 会撞守卫；豁免逻辑做成纯函数可单测（防 DNS rebinding 保留、跨站写不放开、前缀伪造 `/callbackX` 不越权）。tenant token 按账号分键缓存（v1 是模块级单缓存，多账号必然互踩）。
- **前端**：账号页新增 `SyncSettings.tsx`（配置表单 + 探测绑定 + 停用 + 扫码授权发起/解除 + Device Flow 注册：二维码经 vite alias **只读引用** v1 `vendor/qrcode-generator.js` UMD 渲染 SVG，2s 轮询节流双保险）；`Editor.tsx` 加「上报到飞书 / 飞书版本 / 恢复此版本」同步条（恢复 = `POST /sync/restore` 取回文本 → 校验 `data.sections` → `setDraft` → 800ms 自动保存落库）。
- **验收**：新增 `test/sync.e2e.test.ts` **43 条**（纯函数 8 + 回环守卫豁免 5 + 配置与隔离 10 + 上报/版本/恢复 7 + OAuth 6 + Device Flow 5 + legacy 回退 2），内存 PGlite + stub 飞书全链路，**不需要真实凭证、绝不打外网**；**五组变异全部证伪有效**（配置查询去 userId 过滤 → 19 红、脱敏回传 secret → 4 红、回调不验 state → 1 红、去轮询节流 → 2 红、豁免放开非 GET → 1 红），还原后全绿；合计 **137 通过 / 3 跳过**、`npm run build` 通过；真实 HTTP **32/32**（未登录全端点 401、legacy 回退生效、保存脱敏、secret 留空沿用、404/400 语义、伪造 Host 403、跨站豁免真打通、state 一次性防重放、显式停用不回退）。
- **验收残留清理**：HTTP 验收曾在演示账号写过假凭证（覆盖 legacy 回退），按 PGlite 单进程铁律停 dev → `DELETE FROM sync_configs / sync_oauth` → 重启，恢复「无 DB 行 → 回退 v1 真实 `sync.config.json`」的原始状态；resumes 10 份未受影响。

## 9. 错误与修复登记表（按性质分组，勿退回）

### 环境与选型
| 现象 | 根因 | 修复 / 结论 |
| --- | --- | --- |
| 系统级 PG 装不上 | 无 sudo、无 brew/docker、`/opt` 不可写 | 改用 PGlite（同方言） |

| `node:sqlite` 虽可用 | 方言差异会逼着重写 schema | 不采用，仅作为环境可行性记录 |

### 框架 / 构建
| 现象 | 根因 | 修复 |

| 现象 | 根因 | 修复 |

| 现象 | 根因 | 修复 |
| --- | --- | --- |

## 11. 诚实降级与已知边界

- 找不到 headless Chrome → 矢量 PDF 返回 501 并提示浏览器打印另存，不静默失败。
- 没有 CDP 调试端口 → 采集返回引导 hint，不伪装成功。
- 未配置 AI → 状态接口如实报未配置，试用台禁用；`ai.config.json` 只读回退，显式停用优先。
- `validateBaseUrl` 不解析 DNS，**不防 DNS rebinding**；正式对外部署需在出口网关限制。
- `COOKIE_SECURE=false`、仅监听回环；当前安全模型只适用于 ≤10 人本机内测。
- `share_grants` 表已建但分享 API 未接入；N3 的「shareToken 无远程吊销」历史限制在 v2 里具备解决条件但尚未落地。
- 飞书同步：代码与无凭证路径已完成（栢测试 43 条 + HTTP 32/32），但**真实扫码 / 真实上报 / Device Flow 真注册未端到端验收**（需真实凭证与扫码）；回调端口 3000 需在飞书开放平台登记；v1 的 8000 端口同步链路仍独立可用，两套系统的云盘锚点各管各的（v2 首次上报会在飞书另建一套文件/文档）。
- AI 目前只有转发层，未接 JD 派生 / 润色等写作流程。
- v2 不支持 `file://` 单文件离线版与 Tauri 壳；v1 仍保留该能力。
