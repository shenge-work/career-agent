# 02 · 架构、数据模型与接口清单

## 1. 进程与端口

```
浏览器 ── http://127.0.0.1:5173 ──> Vite dev server（React SPA）
                 │  /api 代理（changeOrigin: false）
                 v
             http://127.0.0.1:3000  NestJS + Fastify
                 │                     ├─ PGlite（进程内，数据目录 v2/pgdata/）
                 │                     ├─ 只读引用 v1 源码与 css（LEGACY_ROOT）
                 │                     └─ 按需 spawn：headless Chrome（PDF）/ boss-collect.js（采集）
v1 独立运行：http://127.0.0.1:8000（tools/serve.js）── 与 v2 不共享数据、不互相调用
```

- 两个服务都只监听 `127.0.0.1`；Vite `strictPort: 5173`，API 默认 `PORT=3000`。
- 迁移脚本、直接读写 `pgdata` 的核查脚本必须与 dev 服务**互斥运行**（PGlite 单进程）。
- 验收时额外起过 headless Chrome 调试端口 9223（CDP），属临时进程，不属于部署拓扑。

## 3. 数据表（`src/server/db/schema.ts`）

| 表 | 主键 | 关键列 | 说明 |
| --- | --- | --- | --- |
| `users` | `id` (uuid) | `email`(唯一)、`password_hash`、`role` admin/member、`status` active/disabled、`last_login_at` | Argon2id hash |
| `sessions` | `id` | `user_id`、`token_hash`(唯一)、`expires_at`、`revoked_at`、`user_agent`、`ip` | cookie 里只放随机 token，库里只存 sha256 |
| `resumes` | `(user_id, id)` | `title`、`kind` master/derived/blank、`parent_id`/`job_id`/`jd_text`、`tags` jsonb、`is_master`、`payload` jsonb、`saved_at` | payload 原样承载 v1 文档（`data`/`fonts`/`spacing`/`v`/`savedAt`），不裁剪字段 |
| `versions` | `id` | `user_id`、`resume_id`、`kind`、`label`、`snapshot` jsonb | 快照不含 savedAt |
| `companies` | `(user_id, id)` | `name`、`payload` jsonb | 纯公司背景，`applied` 仅作隐藏关联标记 |
| `company_jds` | `(user_id, id)` | `company_id`、`payload` jsonb | 岗位 / JD |
| `tracker` | `(user_id, id)` | `company_id`、`payload` jsonb | 投递记录；`payload.chat[]` 是 IM 聊天事实源 |
| `share_grants` | `id` | `user_id`、`resume_id`、`token_hash`、`permission`、`expires_at`、`revoked_at` | **已建表，本轮未接入 API**（为 N3 分享预留） |
| `settings` | `user_id` | `payload` jsonb | `PUT` 走 `jsonb \|\|` 合并，非整包覆盖 |
| `ai_configs` | `user_id` | `provider`、`base_url`、`api_key`、`models` jsonb、`temperature`、`timeout_ms` | `api_key` 只留服务端；空行 = 显式停用 |
| `ai_usage` | `(user_id, day)` | `requests`、`errors`、`last_at`、`last_model` | 按账号 + 本地自然日累计 |
| `sync_configs` | `user_id` | `app_id`、`app_secret`、`domain`、`folder_token`、`doc_title`、`file_name`、`file_upload_mode`、`dry_run` | P2b-II：应用身份配置；secret 只留服务端，GET 脱敏；DB 无行时只读回退 v1 `sync.config.json`，空行 = 显式停用 |
| `sync_oauth` | `user_id` | `access_token`、`refresh_token`、`expires_at`(bigint 毫秒)、`refresh_expires_at`、`scope` | 扫码授权的用户身份凭证；不回退 v1 文件（两套系统云盘锚点各管各的） |
| `sync_state` | `(user_id, resume_id)` | `document_id`/`file_token`（app）与 `user_document_id`/`user_file_token`（user） | 每份简历 × 认证模式的飞书锚点；分列即 v1 `authStateKey` 分键隔离的 SQL 化 |

**复合主键的由来**：v1 的 id 全由客户端生成（`res_*` / `co_*` / `jd_*`），多账号下必然可能撞 id。若主键只有 `id`，A 用户导入会覆盖 B 用户数据。`drizzle/0001_tenant_pk.sql` 把四张业务表改为 `(user_id, id)`，与「所有查询必带 user_id」构成同一套隔离语义。

**迁移机制**：`migrate.ts` 顺序应用 `drizzle/*.sql`，用 `_migrations` 表记录已应用文件；不依赖 drizzle-kit 在线连接。`db:generate` 的输出只用于比对 DDL 漂移（实测与手写基线一致）。三个迁移均已应用到 `pgdata`：`0000_init` / `0001_tenant_pk` / `0002_ai`。

## 4. 隔离与认证（铁律）

- `TenantDb.forUser(userId)` 返回的对象里**不存在任何不带 userId 的查询方法**；controller 只能通过 `BusinessService → TenantDb` 访问数据。
- 典型模式：`where(and(eq(table.userId, userId), eq(table.id, id)))`；别人的资源一律 404，不是 403（避免泄露存在性）。
- 业务控制器统一 `@UseGuards(SessionGuard, RolesGuard)`；登录与探活端点用 `@Public()` 例外；`/api/users` 需 admin。
- 会话：HttpOnly + SameSite=Lax cookie（`COOKIE_SECURE` 默认 false，仅适用于本机 http）；`revokedAt` / `users.status` 让登出与停用即时生效；`LoginThrottle` 进程内限流。
- 请求边界：`security.ts` 的 `assertLocalRequest` 校验 Host 必须回环、Origin 若存在必须回环、`Sec-Fetch-Site: cross-site` 拒绝；**端口不固定**（放行 Vite 5173 → 3000 的代理）。只在 `main.ts` 的 Fastify `onRequest` 注册，`app.inject()` 测试不经过。**例外**：飞书 OAuth 回调（`/api/feishu/oauth/callback`）是浏览器从飞书域 302 跨站抵达，按 `CROSS_SITE_ALLOWED_PREFIXES` 精确前缀豁免——仅 GET、Host 仍须回环（防 DNS rebinding），回调必须携带 start 签发的 state。

## 5. 渲染引擎孤岛与两条 PDF 链路

**为什么是服务端 vm 沙箱**：v1 的 `renderResumeInner` 是命令式 DOM 资产，重写成 JSX 会让分页 / 打印契约全部失效。`legacy-renderer.ts` 按 `index.html` 顺序加载 v1 八个脚本（`data.js`、`resume-store.js`、`editor-schema.js`、`resume-render.js`、`export-pdf.js`、`feishu-sync.js`、`pane-mobile.js`、`app.js`），调 `ResumeEditor.applyImported(payload)` 取 `preview.innerHTML`，内联 `css/style.css` 拼 A4 HTML。

| 约束 | 原因 |
| --- | --- |
| **每次渲染新建 vm context** | v1 的 `data` / `currentFonts` 是脚本顶层 `let` 全局态，复用会跨用户串数据 |
| `ctx.window = ctx` | IIFE 的 `global` 才能落到沙箱上 |
| 定时器用成套 no-op | 真定时器会在 context 销毁后访问浏览器对象 |
| `<title>` 必须 `escapeHtml` + CSP `script-src 'none'; object-src 'none'` | payload 不可信，防 `</title><script>` 注入 |
| `mmNum` 对 null / '' 显式回退 14mm | `Number(null) === 0` 老坑 |
| `@page` 边距跟随 `payload.data.pageMargins` | 与 v1 `tools/render-resume.js` 同源 |

**矢量版**（默认）：`pdf.service.ts` 用 headless Chrome `--print-to-pdf`，文字可选中；找不到浏览器抛 `NoBrowserError` → HTTP 501 并提示「浏览器打印另存」，不静默失败。

**图片版**（`?mode=image`）：`legacy-export-html.ts` 生成自执行导出页（内联 v1 bundle + 本地 `vendor/html2canvas.min.js` / `jspdf.umd.min.js`、DOM 哑元素兜底、`confirm/alert` 桩、payload `</script>` 转义、CSP `connect-src 'none'`），driver 自动 `applyImported → exportPDF → downloadPDFNow()`；`image-pdf.service.ts` 用 `--remote-debugging-port=0` + `DevToolsActivePort` 启 Chrome，`Browser.setDownloadBehavior` 让 Chrome 下载落盘，轮询 `window.__RESULT__` 与文件体积稳定后读回。

**分页契约（v1 三条铁律，勿退回）**：
1. 分页点一律走 `RB.computePageBreaks(cap.clone)`，量的是**被截图的克隆**；内部 `collectInkBoxes` + `snapBreaksToBoxes` 做「不切行吸附」。
2. `.reorder-btns` 只能 `visibility:hidden`，**禁止 remove**（它是 inline-flex 实体盒子，删掉克隆会比预览矮一截）。
3. 克隆与预览必须同高；页高越界时等比缩小兜底。

测试通过 monkey-patch `RB.getPageMetrics` / `computePageBreaks` 探针实测：`rootIsClone=true`、克隆与预览同为 `794×2727`、断点 `[0, 1017, 2033, 2621]` → 3 页。

## 6. AI 转发与 BOSS 采集

| 模块 | 行为 |
| --- | --- |
| `ai-config.ts` | 纯函数：配置归一化、脱敏 `publicConfig`（只给 `hasApiKey`）、`validateBaseUrl`、请求体白名单 |
| `validateBaseUrl` | 只允许 https 公网域名 / http 仅回环（本地 Ollama、测试桩）；拒绝字面私有与保留 IP（含 `169.254` 元数据）、userinfo、query/hash、`..`。**不做 DNS 解析，不防 DNS rebinding**，正式部署需出口网关限制 |
| `ai.service.ts` | DB 配置优先 → v1 `ai.config.json` 只读回退（`AI_CONFIG_FILE` 可覆盖）；显式清空 = 停用、不再回退；`PUT` 留空沿用旧 Key |
| `POST /api/ai/chat` | Fastify `reply.hijack()` + `Readable.fromWeb(upstream.body).pipe(reply.raw)` 逐 chunk 透传；`req.raw.on('close')` 取消上游；`app.inject()` 与 Vite 代理均实测可收完整流 |
| `ai_usage` | 每次请求按账号 + 日期累计 `requests` / `errors`，账号页可见 |
| `collect.service.ts` | spawn v1 `tools/boss-collect.js`（`BOSS_COLLECT_SCRIPT` 可注入 fixture、`COLLECT_TIMEOUT_MS` 可缩），端口限 1–65535、url 限 http(s)，20s 超时 SIGKILL |
| 去重与落库 | 精确 `role+text+时间戳` + 宽松 `role+text`（宽松集合**只从既有消息构建**，保留同批重复）；服务端直接并入 `tracker.payload.chat`，**取代 v1 的 `seed.json` → localStorage 通道** |
| `GET /api/collect/status` | 报脚本可用性与默认端口；无 CDP 时 `POST` 返回引导 hint，不伪装成功 |

## 9. 数据现状与产物

- 迁移结果：**10 份简历**（8 条索引 + 1 份未索引空白简历 + 1 份旧版单文件 `data/resume.json`）、**6 家公司**、**4 份 JD**、**3 条投递**、`settings.activeResumeId`；派生关系、tags、isMaster、投递→公司关联均保留。旧 `data/` 零改动。

> AI生成
