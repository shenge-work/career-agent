> 需求侧的唯一总入口仍是 [../需求文档/00-需求总览.md](../需求文档/00-需求总览.md)；本目录是「资料与结论」的沉淀，不替代需求文档。

## 为什么单独建这个目录

项目 `.gitignore` 排除了整个 `data/`，而本次所有结构化调研成果都落在：

- `data/companies/companies.json` —— 6 家公司档案、16 条调研、4 份岗位 JD
- `data/tracker/seed.json` —— 3 家公司、22 条 IM 聊天种子

也就是说，**这些数据不会进版本库、换机器就丢、也无法在仓库里被检索**。本目录把其中可公开的部分固化为可入库的 Markdown 快照，并给出可复现的导出管线，让「调研结果」真正沉淀下来。

事实源与快照的分工：

| 层 | 位置 | 作用 | 是否入库 | 能否手改 |
|---|---|---|---|---|
| 事实源 | `data/companies/companies.json` | 应用读写的唯一真实数据 | 否（私有） | 应用内录入或改 JSON 后重跑导出 |
| 可读快照 | `docs/公司调研/公司情报汇总.md` | 人读、可检索、可 diff、可交接 | **是** | **否，自动生成** |
| 完整版 | `data/公司情报汇总-完整版.md` | 未脱敏本地查阅 | 否 | 否 |
| 结论沉淀 | 本目录 `*.md` 纪要 / README | 决策、边界、待办 | **是** | 是 |

> 单一事实源铁律：任何数据修正都先改事实源，再重新生成快照；**不要直接编辑 `公司情报汇总.md`**，否则下次导出会被覆盖。

## 更新流程

```bash
# 1. 在应用「公司档案」录入或编辑资料（或直接改 data/companies/companies.json）
# 2. 重新生成可读快照
npm run research:export

# 3. 提交前校验快照是否与事实源一致（过期会返回非零退出码）
npm run research:check

# 需要未脱敏完整版（仅本地，不入库）
npm run research:export -- --private
```

`package.json` 中对应脚本：`research:export` / `research:check`。

## 脱敏与边界规则

导出脚本默认产出**可入库版**，遵守以下规则：

1. **招聘者姓名脱敏**：已带称谓（先生 / 女士 / HRBP 等）保留，完整姓名改为「姓 + `*`」（两字姓名 → `X*`）；映射从全库 JD 自动收集，新增 JD 无需改脚本。
2. **公司侧不出现投递内容**：早期从「BOSS直聘求职记录」整段粘进 `research[]` 的历史条目含投递上下文，导出时**不计入六维调研、不作公司背景资料**，单列「附：历史导入条目」并注明建议迁往投递板块；原文仍完整留在事实源。
3. **IM 聊天正文不进公司快照**：聊天归投递板块（`data/tracker/seed.json`），本目录只记录其数量与位置。
4. **不外发完整版**：`--private` 产物落在 `data/`，含未脱敏姓名，不要复制进可入库文档或对外分享。
5. 提交前按项目惯例扫 PII：`git grep` 检查真实姓名与公司敏感信息。

## 本次调研结论摘要

1. **职责边界是本轮最大收获**：公司板块 = 纯公司背景档案（含 JD 索引），投递板块 = 平台 / 状态 / IM 聊天；公司侧不出现任何投递状态，跨板块只读回链。
2. **内容要按数据类型拆模型**：相册、福利、风闻、薪资、链接、融资轮次、转型阶段各自独立成数组，不能一股脑塞进 `research[]`；两张时序图用结构化事件数据 + 原生 SVG，不替换原文本调研。
3. **图片存储是最大技术风险**：零后端 + 单 JSON + localStorage 5MB + `file://` 四者叠加，图片不能内联进 JSON；建议本地媒体目录 + 同源托管。
4. **行业检索要用受控词表**：现有 `industry` 是自由文本，搜「大模型」命中不了「AI 应用」；需类目词表 + 别名表 + 旧数据推断，类目与自由标签不合并。
5. **图片简报可复用已有基建**：`vendor/html2canvas.min.js` 离线可用，零新增依赖；关键是导出强制浅色底、外链图归一为同源 / data URI、八卦默认排除。
6. **最该补的是决策闭环**：`verdict`（我的判断 / 待核实问题清单）、`interviews[]`（面试与面经）、信息新鲜度与来源冲突标记、统一 `SourceRef`、通用 `TimelineEvent`、录入口径字典。

完整推导见[调研纪要](./2026-11-03-公司档案板块需求调研纪要.md)；9 个待拍板决策点见 [D7 §十二](../需求文档/D7-公司档案板块设计.md)。
