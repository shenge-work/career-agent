## 一、一句话方案

CareerAgent 的跨设备同步采用 **「哑云（dumb pipe）+ 端到端加密（E2EE）+ 可替换 Transport」** 架构：云端**不建业务库、不理解业务内容**，只做四件事——设备授权、分配严格递增序号、存加密事件流、存加密 blob。冲突判定（HLC + LWW）、软删除、冲突快照、人工恢复**全部在本地完成**。换云厂商 = 换一个 `SyncTransport` 实现，本地业务代码一行不改。

当前首选通道：**腾讯云轻量服务器自建**（`https://106.55.30.22`，SQLite + 磁盘 blob）；Cloudflare Workers + D1 + R2 冻结待定、腾讯云 CloudBase 备选未部署，三套后端共用同一份 `/v1` 协议与 handler。

## 二、为什么是「哑云 + E2EE」（选型决策）

### 2.1 核心结论

| 判断 | 理由 |
|---|---|
| 云端不建业务库 | HLC 授时 / LWW / 软删除 / 冲突快照 / 恢复已全部由本地 0010~0012 完成；E2EE 下云端只见密文，托管 PG 的触发器 / RLS / Realtime 全部失效，建库纯属浪费 |
| 端到端加密 | 密钥只在本机，云端存 `sha256(authKey)` 与密文，即使云端被拖库也拿不到明文 |
| 可替换 Transport | 协议契约固定，云端只是「存储 + 序号分配」，换厂商成本 = 一个 `SyncStore` 实现 + 一个入口 |

### 2.2 候选方案对比（2026-11 口径）

| 候选 | 成本 | 国内访问 | 结论 |
|---|---|---|---|
| **腾讯云轻量服务器自建（当前首选，已上线）** | 复用已有 VPS，零新增成本；2 核 2G 够单人 | 公网直连、最稳 | ✅ 复用 `/v1` 协议 + `handler.ts`，SQLite + 磁盘 blob |
| Cloudflare Workers + D1 + R2 | 免费档够单人；超额 $5/月起 | `workers.dev` 不稳，需绑自定义域 | 🧊 冻结：R2 订阅卡结账页、境内不可达；代码原样保留 |
| 腾讯云 CloudBase / COS | 免费 3000 资源点/月 | 最稳、数据境内 | 已接入代码未部署；控制台 UI 自动化在本机不可用，留作备选 |
| 自建 NestJS + PG（多用户 SaaS） | VPS + 域名 + 证书 | 完全自控 | 留给将来多用户；单人用轻量服务器版即可 |
| Supabase 托管 PG | 免费 500MB DB / 1GB 存储 | 常超时 | 否决：E2EE 下其全部优势失效 |
| 离线增量包（任意网盘） | ¥0，零账号零运维 | 不涉及 | 第一阶段先行交付，也是 Sync Engine 零依赖验证环境 |

## 三、三序号铁律（最容易写歪的地方）

同步系统里存在**三个互相独立的时钟/序号**，职责绝不混用：

| 序号 | 作用域 | 职责 | 生成方 |
|---|---|---|---|
| `change_log.hlc` | 本机 | **本地增量拉取游标**（outbox），只在本机有效 | 0010 单序列，严格单调 |
| 业务行 `hlc` | 跨设备 | **跨设备 LWW 因果时钟**，随事件封包 | 0011 `ca_hlc_state` 统一领号 + observe 远端 |
| 云端 `seq` | 全局 | **断点续传**，20 位定长字典序 = 数值序 | 云端分配 |

配套两条铁律：

- **seq 刻意不进 AAD**：否则服务端分配 seq 后密文解不开（AAD 在加密时已固定，而 seq 是 push 时才分配）。seq 完整性改由 pull 时「严格递增且与 nextSeq 吻合」校验。
- **推事件必须带整行**：0010 的 `change_log.payload` 只是轻量信号（`table/op/id`），不含整行。push 前必须按 entity/entityId 读当时的完整业务行快照填 `SyncEvent.row`；回灌走 `applyRemoteUpsert()`。

## 四、协议契约（`src/server/sync/`）

### 4.1 核心类型

- `transport.ts`：`SyncEvent`（entity/entityId/op/row）、`SyncEnvelope`（seq/deviceId/ciphertext/aad）、`SyncTransport` 接口、CAS 冲突 `SeqConflictError`、`INITIAL_SEQ`、`SYNC_PROTOCOL_VERSION`。
- `SyncTransport` 方法：`head() / push(envelopes, expectedSeq) / pull(since, limit) / putBlob / getBlob / hasBlob / deleteBlob`。

### 4.2 云端 `/v1` 端点（三套后端一致）

| 端点 | 作用 |
|---|---|
| `POST /v1/vaults` | 建 vault（同 id 禁止重置授权），只提交 `sha256(authKey)` |
| `GET /v1/vaults/:id` | 含公开 salt |
| `POST /v1/vaults/:id/devices` | 登记设备 |
| `GET /v1/vaults/:id/head` | 当前 head seq |
| `POST /v1/vaults/:id/events` | CAS 推（`expectedSeq` 落后返回 409） |
| `GET /v1/vaults/:id/events?since=&limit=` | 拉取增量 |
| `PUT/GET/HEAD/DELETE /v1/vaults/:id/blobs/:objectKey` | blob 读写探测删除 |
| `GET /v1/health` | 部署自检 |

### 4.3 安全与一致性

- `X-CA-Auth` 在 TLS 内提交 authKey，云端只存 `sha256(authKey)` 常量时间比对。
- 云端只写 `aad`（路由信息）与密文，绝不解密；校验 `vaultId/deviceId/batchId/index` 一致性，挡跨 vault 重放与批内乱序。
- CAS 靠 `events` 主键 `(vault_id, seq)` + 单事务：落后游标 409，并发撞主键整批回滚，不产生序号空洞。
- 限额：单批 200 条 / 单条 512KB / 单请求 4MB / blob 25MB；`objectKey` 只接受 64 位 hex 防路径穿越。

## 五、密钥体系（`crypto.ts`）

恢复码与登录账号**解耦**：启用同步时本地生成一次性恢复码，另一台设备输入同一恢复码即可加入 vault；改登录密码不影响同步密钥，也不需要邮箱找回。

派生链：

```
恢复码 → scrypt(恢复码, salt) → masterKey
       → HKDF → { vaultId, authKey, encKey, macKey }
```

- **事件与 blob 均 AES-256-GCM**；AAD 绑定 `vault / device / batch / index`。
- **`objectKey = HMAC(macKey, sha256(明文))`**：兼顾保密（不暴露内容指纹）与同用户去重（同内容同 key，重传幂等）。
- **云端只存 `sha256(authKey)`**，从不下发明文密钥。
- **salt 自包含**：`recoveryCodeSalt()` 从恢复码确定性派生公开 salt，所以只需抄一串码；`deriveVaultKeys(code)` 即可派生同一 vault 跨设备加入；`deriveVaultKeys(code, salt)` 旧签名保留给离线包与历史数据。

## 六、本地冲突地基（迁移 0010~0014）

> 这是「云端为什么可以是哑的」的前提——所有语义都在本地完成。

| 迁移 | 内容 |
|---|---|
| `0010_business_change_log` | 12 张业务表 AFTER 触发器自动写 `change_log`（含删除墓碑），与业务写同事务；游标由 DB 单序列统一授时 |
| `0011_sync_semantics` | 业务表加 `hlc/device_id/deleted_at`；BEFORE 触发器统一授时 + observe 远端；8 张实体表软删除 + 读过滤 + 同 id 复活；跨设备回灌按 HLC LWW，落败方整行留 `conflict_snapshots`；`tracker.chat[]` 投影 append-only 事件流 |
| `0012_conflict_restore` | 冲突快照加 `status/resolved_at/restored_from` 状态机；`restore` 翻译业务列成新本地写（新 HLC + 本机归因 + change_log，绝不回拨时钟） |
| `0013_sync_state` | per-user 同步状态表（vaultId/deviceId/pushedCursor/pulledSeq/keysJson/status/knownBlobs/lastSyncAt/lastError） |
| `0014_stale_echo_guard` | 堵「陈旧回声」回退洞（见 §9 踩坑） |
| `0015_referrals` | 内推表（纳入同步表，复用 0010/0011 触发器） |

**回灌铁律**：云端行落本地必须包 `withSyncImport()` / `applyRemoteUpsert()`（会话 GUC `app.sync_import='on'`）；窗口内保留远端 hlc/device_id、`change_log` 写入被吞掉防成环，try/finally 复位。

## 七、Sync Engine（`engine.ts`）

### 7.1 一次 `syncOnce` 三阶段

```
syncOnce = pull → push → GC
```

三阶段**各自独立推进游标**，中断可续：

1. **pull**：按云端 seq 拉增量 → `openEvent` 解密 → `applyRemoteUpsert` 回灌。每批落一次 `pulledSeq`，中断只重放最后一小段。
2. **push**：`pushedCursor` 为空 = 首次启用 → **基线全量首传**（10 张同步表当前活跃行）；否则读 `change_log` 增量 → 按 entity/entityId 读完整行快照 → 封包上云。CAS 冲突先 pull 再重试（≤5 轮）。
3. **GC**：本地 blob 按活跃引用集清理；云端 blob 按 `knownBlobs` 比对引用集 `deleteBlob`。

### 7.2 关键机制

- **基线首传跳过回声**：设备 B 加入时先 pull 再基线推送，会把自己刚拉到的行原样推回；配合 0014 守卫 + 引擎「跳过与本轮拉到版本一致的行」，避免回声污染。
- **附件 blob 先传后推**：附件事件先 `sealBlob` 上传，再推行；本地字节缺失（remote_only 降级）不阻塞行落地，下次重试。
- **附件回灌 LWW**：attachments 无 0011 行守卫（hlc 应用层维护），回灌时引擎自己做 LWW 判定（严格更新才拒收）。
- **10 张同步表**：`resumes / companies / company_jds / referrals / tracker / applications / portfolios / interview_notes / interview_kb / attachments`。

### 7.3 服务编排（`sync-cloud.service.ts`）

恢复码 → 派生密钥 → 建/加 vault → 建 `sync_state` 行（全字段）→ 启动引擎。对外接口（`sync.controller.ts`）：`status / setup / disable / sync / recovery`。`sync_state` 行由 service 先建全字段，引擎内 `patchState` 只做纯 UPDATE（避免 drizzle upsert 给缺失列填 NULL 撞 NOT NULL）。

## 十、部署方案（自建通道，当前线上）

### 10.1 架构

```
桌面客户端 ──HTTPS(自签名)──▶ 106.55.30.22:443
                                 │  systemd: ca-sync.service（User=ubuntu）
                                 │  Node 22 + better-sqlite3
                                 ├─ sync.db（vaults/devices/events）
                                 └─ blobs/（磁盘内容寻址，重传幂等）
```

### 10.2 关键决策

- **服务端内置 HTTPS（自签名）**：`server.ts`/`index.ts` 读 `TLS_CERT_PATH`/`TLS_KEY_PATH`，无需 nginx/Caddy。自签名是临时方案，有域名后换 Let's Encrypt，业务代码零改动。
- **客户端 `insecureTls`**：`RemoteSyncTransport` 新增 `insecureTls` 选项，走 `undici` 的 scoped dispatcher（`rejectUnauthorized:false`），**仅作用于同步请求**，不污染进程内其他 HTTPS。
- **监听 443**：`setcap cap_net_bind_service=ep $(readlink -f /usr/bin/node)` 让非 root 的 ubuntu 用户绑特权端口，客户端 baseUrl 无需端口。
- **部署脚本** `cloud/sync-server/scripts/deploy.sh`：装 Node 20（已装则跳过）→ `npm install --omit=dev` → 生成自签名证书 → 写 `.env` → 注册 systemd → 启动。

### 10.3 部署后自检

```bash
# 服务端本地
curl -k https://127.0.0.1:443/v1/health          # → {"ok":true,"v":1}

# 客户端公网端到端（含 deleteBlob）
NODE_TLS_REJECT_UNAUTHORIZED=0 BASE_URL=https://106.55.30.22 npm run smoke
```

冒烟 8 组用例：health / 建 vault / E2EE 推拉解密还原中文 / CAS 409 / blob 加密往返 / blob 删除幂等 / 跨 vault 隔离 / 未授权 401。
