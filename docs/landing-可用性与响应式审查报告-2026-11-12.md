# CareerAgent 落地页 · 可用性与响应式审查报告

> 审查对象：`landing/index.html`、`landing/css/style.css`、`landing/js/main.js`
> 审查范围：可用性（UX）/ 响应式适配 / 视觉一致性
> 审查方式：UI 设计全栈专家团（视觉 / 体验 / 前端工程三位专家并行审查，主理人汇编）
> 日期：2026-11-12

---

## 一、总体结论

**审美方向与信息架构正确，执行层面的「收敛」不足。**

- **做得好**：靛蓝主色 + slate 中性 + 白底的克制定位清晰；痛点 → 方案 → 功能 → 信任 → 下载的叙事层层递进；标题层级（单 h1 → h2 → h3）无跳级；landmark 基本齐全；移动端汉堡菜单、按钮全宽、极窄屏 app-window 处理均正确；对比度整体达标；深色信任区与 footer 做到了同值呼应。
- **核心短板**：① 移动端**无 JS 时导航彻底失效**（渐进增强缺失）；② **下载按钮指向占位 URL 且文案过度承诺**，是全页转化与信任的头号风险；③ 键盘 / 低动态用户的 a11y 细节（焦点样式、Esc 关闭、reduced-motion、skip link）未补齐；④ 设计 token 只搭了骨架，色值 / 圆角 / 字号 / 间距 / 图标尺寸五条轴线存在大量「逐组件硬编码 + 1~2px 无意义差异」。

## 二、问题清单（按严重程度）

### P1 · 重要（上线前建议必修）

| # | 问题 | 位置 | 影响与建议 |
|---|------|------|-----------|
| 1 | **无 JS 时移动端导航彻底失效** | `index.html:70-74`、`css:918-939`、`js:80-100` | ≤720px CSS 默认把 `.nav-menu` 置为 `visibility:hidden`，而展开完全依赖 JS。无 JS / JS 加载失败时，移动用户既打不开菜单、菜单又被 CSS 藏起，锚点导航全部失效。**建议**：渐进增强——用 JS 给 `<html>` 加 `.js` 类，隐藏规则改为 `.js .nav-menu{…}`，无 JS 时菜单默认可见；或改用原生 `<details>/<summary>`。 |
| 2 | **下载按钮是占位 URL，标签却承诺「下载」** | `index.html:111/123/459-467/486-494`、`js:31-34` | 按钮文案「下载 Windows/macOS 版」暗示直接下载文件，实际跳 GitHub Releases 列表页；仓库尚未发布 release 时会 404。**建议**：正式发布后把 href 改为直达资源 `…/releases/latest/download/CareerAgent-Setup.exe` / `…/CareerAgent.dmg`；未发布前按钮置灰为「即将发布」或改文案「前往下载」。注意 `js` 的 `applyDownloadLinks` 只是把同样的占位值写回，并未解决问题。 |

### P2 · 一般（发布后尽快修复）

| # | 问题 | 位置 | 影响与建议 |
|---|------|------|-----------|
| 3 | **缺少自定义可见焦点样式** | 全站（无 `:focus-visible` 规则） | 靠浏览器默认 outline，跨浏览器不一致，`.btn-primary` 上焦点环不明显，键盘用户难定位。**建议**：` :focus-visible{outline:2px solid var(--primary);outline-offset:2px}`。 |
| 4 | **`scroll-behavior:smooth` 未尊重 `prefers-reduced-motion`** | `css:43-44`、`css:158-161/194-206/309-315/577-585/640-648/938` | 晕动敏感用户受平滑滚动 + hover 上浮困扰（WCAG 2.3.3）。**建议**：`@media(prefers-reduced-motion:no-preference)` 才开启 smooth，另加 `reduce` 时 `*{transition/animation:none}` 与取消 hover 位移。 |
| 5 | **移动菜单缺 Esc / 点外关闭与焦点管理，aria-label 不随状态变化** | `js:87-100`、`index.html:70` | 键盘用户展开后只能点 toggle/菜单项收起，无 Esc；焦点不回归 toggle；读屏无法从标签判断开合。**建议**：加 Esc 关闭、点外关闭、焦点移入首项/回归 toggle；aria-label 在「打开/关闭菜单」间切换。 |
| 6 | **缺少 skip link** | `index.html:91`（`<main>` 无 id） | 键盘/读屏每次需 Tab 越过整条导航。**建议**：body 首行加 `<a class="skip-link" href="#main">`，`main` 加 `id="main"`，默认隐藏、`:focus` 显示。 |
| 7 | **触摸目标未达 44×44px** | `css:174-186`（nav-toggle 42px）、`css:297-312`（.btn 约 42px）、`css:829-848`（footer 链接约 24px） | 移动端易误触，footer 链接对胖手指不友好（WCAG 2.5.5/2.5.8）。**建议**：`.btn`/`.nav-toggle` 设 `min-height:44px`，footer 链接加 padding 扩大点击区。 |
| 8 | **footer 在 721–960px 仍 3 栏，过挤** | `css:814-820`（仅 720px 才转 1 栏） | 720px 视口下 3 栏各约 197px，brand 列 tagline 压成 4–5 行；与 download-grid 在 960px 即转 1 栏的节奏不一致。**建议**：footer-grid 在 960px 转 2 栏、720px 再转 1 栏。 |
| 9 | **hero-title 硬编码 `<br>` 在 320–420px 产生孤行** | `index.html:101`（该 `<br>` 无 class，对比 `:104` 的 subtitle 已用 `only-desktop`） | 320px 下标题 28px，前半句 12 个全角字≈336px 超出 272px 内容宽，出现 3 行 + 孤字。**建议**：给该 `<br>` 加 `only-desktop` 类（≤720 隐藏、自然折行）。 |
| 10 | **721–960px 平板区间过早坍缩为单栏，卡片被拉伸** | `css:901-915`（cards-3 / features-grid / download-grid 均在 960px 转 1fr） | 800px 平板下卡片≈752px 宽但仅 2–3 行文字，单栏全宽空荡；download 单卡 752px + btn-block 拉成超长条。**建议**：960px 只让 cards-3 转 2 栏、download 保留 2 栏，720px 才转 1 栏；或 1 栏时给卡片加 `max-width:640px;margin:0 auto`。 |

## 三、修复优先级建议

1. **上线前必修（P1 ×2）**：无 JS 导航失效、下载按钮占位 URL —— 两者都直接影响转化与信任。
2. **发布后尽快（P2 ×8）**：焦点样式、reduced-motion、菜单 a11y、skip link、触摸目标、footer 布局、标题孤行、平板过早坍缩。
3. **一次性收尾（P3 批量）**：做一次「设计 token 收敛」——色值（绿/白/主色阴影）、圆角 4 档、字号整数阶梯、间距与图标标尺、H2/H3 字重语义，可把 11~22 项一并解决；响应式细节（23~29）与 a11y 细节（30~35）随之上线。

> 正面确认（无需改动）：移动端下拉浮层与 sticky header 对齐正确、z-index 无裁剪；app-row 有 `min-width:0`+ellipsis 兜底无横向溢出；viewport 未禁缩放；锚点 id 全部存在且唯一；语义与对比度基础扎实。

- 用 Tab 键走通全站键盘路径，验证焦点可见性与 Esc 关闭菜单。
